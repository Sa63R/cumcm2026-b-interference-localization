# 第二问、第三问的结构与实验表达建议

这份说明从已读原文提炼表达方法，并结合本项目任务设计给出建议；不构成新增实验结论。

## 1. 按模型依赖组织，而非按开发时间写流水账

[2018 A440 范文](https://dxs.moe.gov.cn/zx/a/hd_sxjm_sxjmlw_2018qgdxssxjmjslwzs_2018atlw/240206/1699834.shtml)把基础模型作为后续优化的计算接口：每问只增加相应的变量、目标和约束。它在第 16–18 页先给可行边界和解，再用参数曲线解释约束为何起作用；第 21 页则固定一个参数、改变另一个参数研究机制。

可应用到本项目：第二问完成“信息输入—候选区域—第二观测点选取—定位结果”接口；第三问引用该接口，新增全场发现、待处理集合、访问次序与终止条件。不要在第三问重复整套交会推导。新模块必须交代输入、输出与失败回退条件。

## 2. 保留关键探索，但把结论强度控制在证据内

[2018 B217 范文](https://dxs.moe.gov.cn/zx/a/hd_sxjm_sxjmlw_2018qgdxssxjmjslwzs_2018btlw/240206/1699832.shtml)采用先建立调度约束，再比较数种原则和学习过程的组织方式。第 18 页把学习前后结果放在同一张表，并用转移频数热图解释策略；第 19 页再用时间—位置轨迹说明周期性。

可借鉴“数字差异—行为差异—机制解释”的顺序。范文中将学习未超越基线作为接近全局最优的依据，这个论证**不宜照搬**：学习失败只能说明给定训练与搜索预算下没有找到更优解。当前论文宜保留两个假说：结构化策略利用了情景规律；学习方法仍受训练条件限制。无额外证据时不裁定哪个是假说真相。

## 3. 实验协议写在成绩前面

[Kool 等，ICLR 2019](https://arxiv.org/abs/1803.08475)第 6–7 页将测试实例、训练参数、解码预算、目标值和运行时间放在同一评估框架，并明确说明硬件及实现语言使运行时间难以直接比较。

本项目建议表头包含方法名、代码版本、场景集合、实例数、成功率、任务耗时和推理用时；没有可靠计算时间数据就留待补测或删去这一列。区分四种量：机器人任务耗时、离线训练时间、训练样本量、单步/单局规划计算时间。CPU 核数变化若同时伴随采样量、批量与训练时长变化，只能作为历史资源配置描述。早期和后期结果应分表呈现，不能拼接为同一次四方法比赛。

## 4. 图表要回答明确问题

| 图/表 | 要回答的问题 | 具体表达建议 |
|---|---|---|
| 第二问几何示意 | 第二检测点为什么能缩小候选区域？ | 原点、第一次测向、候选区域、第二检测点、交会角和距离使用统一符号；将示意与真实轨迹区分。 |
| 四方法耗时对比 | 在同一场景集合上谁更省任务时间？ | 均值柱或点图带区间；旁列成功率与样本数；不同版本明确标注。 |
| 配对差值图 | 两种主方法在相同场景的差异有多大？ | 每场景画差值或展示差值分布；定义正负方向；报告配对区间。 |
| 费用分解 | 改善来自移动、扫描还是重复定位？ | 使用日志可核对的动作费用；分量之和必须回到总耗时。 |
| 同场景轨迹小多图 | 路径差异对应什么策略差异？ | 固定场景、地图范围和比例；起终点、观测点、清除点用不同标记；每个面板给真实总耗时。 |
| 核心消融 | 删除某项策略后发生什么变化？ | 每次只改一项，复用相同场景；列变化量、成功率和异常案例。不要把一组大改动称为单策略消融。 |
| 训练行为轨迹 | 原点全扫行为是否自行形成？ | 以训练阶段为横轴展示该行为比例；若只有最终模型日志，就只报告最终模型观察比例。 |

没有日志覆盖的轨迹不得合成；示意轨迹必须明确写“示意”。挑选代表性案例应说明规则，例如按中位耗时附近、最大差异或预先固定种子，避免只展示优势案例。

## 5. 报告不确定性时说明重采样单位

[Agarwal 等，NeurIPS 2021](https://proceedings.neurips.cc/paper/2021/hash/f514cec81cb148559cf475e7426eed5e-Abstract.html)提醒：少数训练运行的点估计不稳定，评估协议变化可产生超过方法差异的影响；第 4–7 页讨论区间、效果大小和性能分布。

本项目若只有一个已训练模型和多场景评估，按场景得到的区间只描述场景抽样变动，不能代表重新训练的随机性。成对使用相同种子时对场景成对重采样。若区间跨零，写“目前数据无法判定平均差异方向”，不要写“两者相同”。同样，区间不跨零也要交代节省量是否具有实际意义。IQM 可作为补充，不能用稳健均值掩盖失败率或极端长尾。

## 6. 方法文献的引用边界

- Held–Karp 用于子集动态规划的来源。只有实际状态和递推一致时才使用该名称，不把任何位掩码搜索都称为 Held–Karp。
- A* 用于启发式路径搜索的来源；加权启发函数、束宽截断、有限预算搜索或不保证下界的评分，不自动继承最优性。
- PPO 与 GAE 只解释实际训练实现中使用的目标和优势估计，不需要展开与当前问题无关的完整强化学习教材。
- 学习方法仍使用几何候选或手工特征时，应完整描述这一设计，避免写成从原始观测完全自主发现所有结构。
- 方法来源进入正文参考文献，国赛范文优先留作写作资料；Kassis 等进入实际软件/辅助工具说明。

## 7. 建议章节骨架

第二问：问题分析与输入约束 → 候选区域构造 → 第二检测点目标 → 可行性及退化情况 → 求解步骤 → 定位例子与解释。

第三问：全场任务与费用模型 → 单源定位接口 → 状态表示与动作空间 → 搜索与调度策略 → 强化学习对照 → 统一实验 → 消融与轨迹机制 → 适用条件和局限。

每个实验段依次交代待检验假设、评估设置、结果和解释；数值结论旁保留来源表或图编号。失败探索仅保留影响方案选择的部分，其余训练日志和超参数清单放入附录。
