# 第三问两种方案与第四问 V4：原理、运行和结果

2026-09-12 发布整理。第三问提供 `v3_origin20`（原点扫描版）和 `optical`（有限提前光学版）；第四问提供已经发布的 `v4_fast`，并保留 `v4` 作为计算对照。这里的版本名称与仓库早期的 `efficient`、`rollout`、`triangular` 不同，使用下文指定的入口。

## 先看三种方案分别做什么

| 题号和方法 | 一句话说明 | 主要适用范围 |
| --- | --- | --- |
| 第三问 `v3_origin20` | 出发时先在原点扫20个频道，再联合安排搜索、测向和清除路线 | 全向源；保留起点观测，可能减少后续绕路 |
| 第三问 `optical` | 在普通v3上增加最多两次提前光学尝试，试中就省去后续测向 | 全向源；允许付出失败尝试的计时成本 |
| 第四问 `v4_fast` | 用21点覆盖保证发现定向源，结合成对测向、光学覆盖和路线重排 | 全向与定向源混合；任务决策与V4相同，计算更快 |

**第三问的两个入口是两个独立版本。** `optical` 继承普通v3的起点设置，默认不做原点全频道扫描；它不是在 `v3_origin20` 上叠加提前尝试。当前没有发布“两项同时打开”的第四种方案，也没有用现有成绩证明该组合更快。

## 第三问原点扫描版

机器人先在原点检测20个频道，用起点信息发现附近的源并获得初始方位。后续把未完成搜索点和已发现目标放在一起规划开放路线，边搜索、边定位、边清除。

定位时维护一个包含真实源的保守候选区域。新的真实测向结果与已有区域相交；测点选择比较移动、本次检测以及预计后续定位费用。清除落点还考虑清除后去下一目标的路程。路线搜索、观测收益估计都是启发式，不是完整问题的全局最优证明。

这个版本不主动尝试未经几何保证的光学清除。通常等到能找到一个点，其20米范围包含整个候选区域，或获得近场反馈，再执行清除。真实成功反馈才会把目标记为已清除。

起点扫描增加了一轮检测费用，也可能更早发现源、减少后续移动，所以不能仅凭“多扫一次”认定它一定更慢。未知频道的排除仍依赖实际扫描覆盖或题目16源上限，未执行的计划测点不算证据。

## 第三问有限提前光学版

普通v3会继续测向，直到得到可以保证清除的落点。提前光学版在位置已经估得较准时，允许先调用一次光学清除：命中就结束该目标；未命中就记录费用，继续原来的定位流程。

当前冻结条件如下：

| 参数 | 数值与含义 |
| --- | --- |
| `max_radius` | 候选区域包围圆半径不超过80米 |
| `threshold` | 当前点的20米清除圆覆盖约40%以上的候选区域面积 |
| `cap` | 每个源最多两次提前尝试 |
| 同点重试 | 同一源在同一坐标不重复提前尝试 |
| 失败处理 | 保留目标和原保守区域；失败不计为清除成功 |

覆盖比例由多边形内面积求积估计，隐含均匀面积假设；40%不是已经校准的真实成功率，也不是几何保证。满足条件时，算法还可能把下一测点选在候选区域的面积重心，以获得提前尝试机会。原有有限次启发式测点与后续定位退路仍保留。

例如，候选区域是一段较短的窄条，机器人走到中部时，20米圆已覆盖其中较大一部分，就可以先试一次。按当前接口语义，未命中耗时3秒，命中共耗时5秒；测向本身耗时5秒，可能另有移动和切频费用。提前尝试用少量失败费用换取省掉后续测向的机会，全部失败尝试都计入成绩。清除动作不会改变测向机频道。

实现见 [q3_optical.py](../experiments/q3_selected/q3_optical.py)。其中算法定义从原试验文件逐字提取，只移除了独立CSV统计入口对pandas的依赖。原文件保存在vendor，发布测试核对函数与类的AST一致性。

## 第四问 V4 与 v4_fast

第四问存在180°半平面发射的定向源。“无信号”可能表示站在源的背面，因此不能直接照搬第三问的全向接收推理。

### 1. 21点搜索覆盖

采用原点1点、半径998米内圈8点、半径1865米外圈12点的布局。1800米是源位置区域的半径，布局外圈用于从外侧发现朝外发射的边界源。

布局具有连续区域覆盖检查：对源域中的位置g，在1000米内的搜索点应从足够多方向包围g，使任意经过g的发射半平面都能遇到至少一个测点。代码用连续几何证书检查整个区域，不把若干网格采样的成功当作完整覆盖证明。

21点是完成未知频道搜索的布局，不意味着每局必须走完所有点。发现16个不同源后可以停止继续搜索未知源，但必须把已发现源全部清除，才算任务完成。

### 2. 成对测向与负观测更新

依据最后一次有信号的位置和方位，在前方两侧构造成对测点。新方位会收缩候选区域；在特定成对几何条件下，两个点都无信号也能排除一部分源位置。一般的单次无信号只按保守约束更新，不会直接丢弃目标。

### 3. 用光学圆覆盖整个候选区域

若已有一个安全清除点，直接执行。否则，当当前区域能由最多12个半径19.5米的光学圆覆盖时，算法依次移动到这些圆心尝试清除，成功即停。19.5米相对物理20米范围保留了余量。

这里保证的是这些圆合起来覆盖整个保守区域，单次尝试仍可能失败。区域过宽或需要超过12个圆时继续测向；全部覆盖点仍未命中会报错，不把目标当作已经清除。

这与第三问的40%面积提前尝试有不同依据：第四问此处先构造完整覆盖，再按真实反馈逐点搜索。

### 4. 每轮成对测向后重新安排路线

定位可以暂停。做完一轮成对测向，就把剩余搜索站和待处理目标重新排序，不必一直追着同一个目标跑。在已经到达的测点、搜索站或清除点，还会选择性地顺便测其他已发现频道，减少额外移动。

### 5. v4_fast 加速的是计算

`v4_fast` 保留V4的行动选择，通过复用重复的包围圆、路线相关计算和覆盖证明中的中间结果降低计算开销。已归档专项测量中，主策略CPU耗时减少32.36%，覆盖证明CPU耗时减少51.76%。两项测量对象不同，比例不能相加，也不能解释为官方整局同比例提速。

动作一致意味着机器人虚拟任务时间一致。此前尝试的动态移站、复杂前瞻等候选，没有在独立再确认中证明稳定收益，因此未替换这里发布的V4任务决策。详见 [第四问运行与验证说明](../experiments/q4_official_practice/README.md)。

## 已有结果应怎样理解

第三问主指标为每局先计算“完整虚拟总时间/源数”，再对案例等权平均；它与所有时间合计除以所有源数的汇总口径不同。

| 第三问方法 | 本地400组相同场景，秒/源 | 全清案例 | 失败光学尝试总数 |
| --- | ---: | ---: | ---: |
| 普通v3，对照 | 242.796 | 400/400 | 0 |
| 原点扫描版 | 243.991 | 400/400 | 0 |
| 有限提前光学版 | 241.736 | 400/400 | 610 |

提前光学版相对普通v3平均省1.060秒/源，约0.44%。失败光学尝试不等于整局失败；上表610次均计费，400局最终全部清除。这些是自建场景，不能当作官方成绩；种子5000—5399曾用于原包验证，不能重新标为从未见过的最终盲测。

随包保存 [1200条逐例数据](../experiments/q3_selected/validation/local_paired400.csv) 和 [汇总及来源哈希](../experiments/q3_selected/validation/local_summary.json)。

另保存北京时间2026-09-12 17:22、九方法批次完成182/900轮时的[官方演练统计快照](../experiments/q3_selected/validation/official_snapshot_182.json)：原点扫描版20轮全清，225.623秒/源；提前光学版21轮全清，236.717秒/源。每种方法使用不同官方地图，源数分布也不同，不能把均值差当作同场景提速证明。这份文件是固定时间快照，不随后台批次更新；它记录整理发布前的历史策略运行，不是本次发布重新跑的官方成绩。

本地配对与官方非配对结果的排序不同，所以不能宣称某个版本在所有场景都最快。第四问数据另行比较；不把两道不同问题的秒/源放在一起排名。

仓库中的其他官方数据评测仍遵循 [固定评测规则](evaluation/OFFICIAL_PRACTICE_POLICY.md)。本次仅整理发布既有策略，没有根据官方快照调参或训练。

## 安装与运行

以下命令从GitHub仓库根目录执行。建议Python 3.12；第三问依赖NumPy，第四问运行仅需标准库。

```sh
python -m pip install -r experiments/q3_selected/requirements.txt
```

第三问不需要pandas。Numba为可选加速依赖；未安装时使用原代码的普通Python路径，数值预热安排在进入官方会话之前。

先在官方模拟器中登录，选择对应题号的**演练测试**，等接口准备完成，再运行相应命令。`YOUR_TEAM_ID`替换为界面上的队号。

```sh
# 第三问：原点扫描版
python experiments/q3_selected/run_practice.py --method v3_origin20 --robot-id YOUR_TEAM_ID --practice-confirmed

# 第三问：有限提前光学版
python experiments/q3_selected/run_practice.py --method optical --robot-id YOUR_TEAM_ID --practice-confirmed

# 第四问：V4计算加速版
python experiments/q4_official_practice/run_speedup.py --method v4_fast --robot-id YOUR_TEAM_ID --practice-confirmed
```

三个命令是备选入口，每条只完成已经准备好的一局。新一局需重新在界面确认题号、演练模式和准备状态；不要对同一个会话同时运行多个程序。HTTP API不能识别或切换演练/正式模式，`--practice-confirmed`只记录操作者的确认。已有双击启动器仍对应其原策略，不会自动切到本页版本。

Windows可以把`python`替换为已安装Python的完整路径，或在激活的虚拟环境中执行。需要记录案例标签时添加 `--case-label CASE_ID`。

第三问结果默认保存到 `results/q3/selected_practice/`；第四问保存到 `results/q4/practice/`。每局保存请求响应、清除计数、计时、版本和源码哈希。这些原始本机日志可能含队号，由Git忽略规则保留在本机。只在接口实际接受清除成功时累计已清除数；请求执行结果未知时保留原请求，停止发送替代动作。
