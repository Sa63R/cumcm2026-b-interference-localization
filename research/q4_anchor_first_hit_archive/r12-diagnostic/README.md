# 可靠 R12 的真实费用与后续方法边界

本诊断只读取已完成并独审通过的可靠 R12 参考 **140 随机 +98 压力**，未运行策略、生成场景或读取源位置作选择。`analyze.py` 对所有真实动作重算微秒移动、检测、换频、光学、移除费用，逐局与保存的 row 一致；从真实正反馈重建 canonical 区域、resolver 入口半径、已知/已清集合和已完成扫描站数。输入逐档 SHA、分 N 汇总见 `diagnostic.json`；全部逐局/逐 resolver 小账本压缩于 `diagnostic-cases.json.gz`。这是已打开参考集的机制诊断，今后不能再把它称为新候选独立验证。

**结论：随机集并非主要被“宽区域主动定位/光学”拖慢。压力集确有这一尾部难点，但不能推广到随机集。两组共同的大项是覆盖几何与清除服务之间的行走。没有找到一条已经证明能省约700秒/局的新规则。**

## 实际费用落在哪里

每格为秒/局；检测和换频是实际动作费，移动按目的动作的 phase 归属，不能把这类归属直接解释为删除该动作后的可省费用。

| 真实 phase | 随机移动 | 随机检测+换频 | 压力移动 | 压力检测+换频 |
|---|---:|---:|---:|---:|
| coverage | 3171.33 | 1484.36 | 3227.26 | 1576.50 |
| certified_clear | 1154.95 | 0 | 690.95 | 0 |
| speculative_clear_before_probe | 390.97 | 0 | 256.20 | 0 |
| active_localization | 166.86 | 12.77 | 644.77 | 65.00 |
| guaranteed_clearance + joint_visibility_optical | 6.55 | 0 | 31.48 | 0 |

全部光学检查费分别仅41.72、53.91秒/局，其中成功清除也有3秒检查。因此只看 optical_s 会漏掉长途进入清除点的移动；但完整光学网格的移动加检查也仅 **8.87/46.51秒/局**。不能据旧失败方法的网格长尾推断可靠 R12 普遍仍在大规模光学遍历。

真实主动无线测量仅 **2.39/12.38次每局**；已ready频道在coverage中的实际扫描为 **0**。现有持证跳扫与range剪枝已生效，不应再次提出“删已ready扫描”当新优化。每局约202.56/223.84次扫描发生在该频道尚未发现时，48.11/42.15次发生于已知但尚未ready时；后者观测既可能提供定位信息也可能no_signal，不能全部无条件删除。

## 真实 resolver 入口，而不是 R34 人为扩大的源集合

| 入口类别/阶段 | 随机次数/局 | 随机整个宏费用 | 压力次数/局 | 压力整个宏费用 |
|---|---:|---:|---:|---:|
| canonical r≤19.9，仍有覆盖义务 | 9.400 | 1045.91 | 7.592 | 643.75 |
| canonical r≤19.9，覆盖义务已结束 | 1.086 | 159.05 | 1.010 | 80.52 |
| 19.9<r≤40，覆盖义务结束后 | 1.571 | 399.65 | 1.408 | 270.99 |
| 原 early，19.9<r≤40 | 0.343 | 13.39 | 0.531 | 15.95 |
| r>40，覆盖义务结束后 | 0.621 | 182.32 | 2.490 | 758.73 |

r>40 的真实 resolver 共 **87次/46个随机案例、244次/70个压力案例**。**没有一个在仍有覆盖义务时启动。** “覆盖义务结束”包括22站实际完成，也包括真实发现16源后的公共上限停止；物理未访问站数与逻辑覆盖义务分别保存在逐宏账本中。

所有案例在覆盖过程中都出现过宽区域；平均每局13个频道曾在某个完成扫描的前缀上仍宽。之后许多频道依靠后续原有扫描自然ready，故“历史曾宽”与“需要专门追宽源”完全不同。R34 的全known服务会主动制造大量更早的宽源宏，不能将它的昂贵路径用于解释 R12。

对 R37 的意义：随机集可作用的宽源宏在现有账本只承载182秒/局，压力则759秒/局。即使后续出口可能产生路径连锁效应，也不能仅凭首探得分宣称同时解决两组约700秒的差距；真实新替代次数和分组费用必须保留。

## 行走的几何分解：约1500秒是费用来源，不是可全部回收的余量

对连续两个实际覆盖站，把中间所有真实服务移动连同进入下一站的移动相加，减去两站直连距离/5。对最后一个实际访问站之后的所有移动另列。由路径三角不等式，站间差额非负；本次逐局重构与实际移动费一致，舍入残差在核验容差内。

| 移动项/秒每局 | 随机 | 压力 |
|---|---:|---:|
| 实际已访问覆盖前缀直接相连 | 3360.78 | 3343.90 |
| 覆盖站之间服务造成的额外路程 | 820.50 | 499.95 |
| 最后已访问站后的服务移动 | 709.87 | 1008.44 |
| 全部实际移动 | 4891.15 | 4852.29 |

后两项合计 **1530.37/1508.39秒/局**，是值得研究的共同大费用项。然而源必须实际访问清除，删除全部源服务当然不合法；这里不称其为可达改进、全局最优gap或700秒保证。

N<16实际走完22站时，固定覆盖直连长度为17612.4194米，即3522.48388秒，已经是该固定站集的MST长度。保留同22站、从原点完整访问的策略不能只靠重新排序将这一纯覆盖项再减700秒。其余可优化性主要是发现/定位时机如何改变服务绕行和尾部，或更换经过独立连续覆盖认证的几何站集。

目标指标是mean(T/N)。按当前均衡N构成，若设想每局统一少同样秒数，随机/压力分别需 **650.37/758.42秒/局**才到460；这只是代数尺度。不能使用mean(T)−460mean(N)=476.01/593.70冒充主指标所需降幅，两者权重不同。

## 16源上限已实现并单独测过

运行链实际使用 `src/strategies/q4_r2_scheduling.py` 的 `_execute_plan`：`discovery_done = len(known)==16`，随后 `covers=[]`，**不要求所有源ready**；未ready源进入完整resolver。更早 `q4_state_search.py` 的all-ready条件在此继承链已经被覆盖。

238份真实记录中，34个N=16案例全部有相应 `discovery_stop_log`，且stop之后coverage动作均为0。随机/压力平均省略6.85/7.57个剩余站。首次得知16源发生在扫描块内部时仍把该站原块做完，其剩余费用在N16案例平均仅15.9/24.0秒（最大48/78）；全组平均只是2.27/3.43秒，且这些剩余测量也可能帮助定位。它不是700秒级的新空白。

独立查重：R2 提交 `ea6839ce` 已有 `cap16` 单配置且early_services=0，`research/q4_round2/development-specs.json` 有独立compact_cap16臂。旧随机24对全清，原T7041.612450→6859.601083，3胜0负21平、均省182.011367秒；压力14对全平。证据在 core `results/q4_round2/{development,development-stress}/summary.json` 和 `research/q4_round2/RESULTS.md`。因此不得再次将它作为新候选。此结论由state agent独立只读复核。

## 后续只推荐一个不同的研究问题

应优先研究**下一原覆盖站的实际信息如何影响已知源的清除时机与共同路程**，而不是再提前追所有宽源、增加A*扩展、重复自由2-opt或重复cap16。

最小可区分提案：保持原22站/所有真实扫描/原ready清除证书，仅在“当前已有ready源可清，且下一原站可能改善另一个已知未ready源”时，比较两条真实合法首宏：先清当前ready源，或先完整扫描下一站。用公开真实P/N形成少量假设，按**共同反馈**更新后继源的区域/目标/ready状态，再比较一段共同服务路径。未来任务位置必须随该分支的假想观测更新；不能只给静止MEC填一个名义release索引或一个固定service常数便称作信息价值。评分应包含源服务后的返回下一站/后继任务路程，并有整次模型失败回退。

这与R36的固定目标+名义release、R5的无观测分支2-opt、R37的当前源新增无线探点均有实质区别；但目前**只有足够大的相关账面费用，没有收益证据**。随机站间绕行820秒与压力尾部1008秒指向不同权衡，模型错判ready/发现时机会恶化另一组。建议先做一个有明确预算的共同反馈服务调度模型，再冻结单候选验证；不要承诺700秒或用这238参考记录调阈值。R38若获得更少站的严格几何证书，也只提供独立几何候选，仍需评估信息弱化是否反增服务路程。
