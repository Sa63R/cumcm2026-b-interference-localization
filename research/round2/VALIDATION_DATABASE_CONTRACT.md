## 代码证据与能力限制

1. `src/practice_control/dataset.py:411` 的 `import_episode` 只读已经保存的演练证据；验证 practice 模式、正常退出、注册结果哈希及完整的 enter-to-exit 日志，再原子插入。它不访问隐藏场景库。
2. `dataset.py:297` 的 `_source_labels` 从已接受的 direction / near / success 约束构造区域，忽略没有严格空间含义的记录；`dataset.py:341` 明确写入 `is_exact_truth=False`。`x_m/y_m` 是所选包络圆的中心，`radius_m` 是源位置误差界，不是源接收半径。`label_json.constraints` 中的 reception radius 是几何推断用的规则上界，不是该源真实接收参数。不能把圆中心当真值、误差半径当无线接收半径。
3. `dataset.py:354` 起的schema保存每次实际动作及实际反馈，没有官方场景源真值、真实接收半径或对任意新位置复现官方噪声的生成器。即使定位误差界很小，也不能唯一决定未记录位置的 near、direction、no_signal 或 clear 反馈。
4. `dataset.py:509` 的 `iter_transitions` 提供历史因果转换，不是可交互环境。其返回值含 `case_code`、split、episode_complete/terminated 等事后元信息；适配给策略时必须剔除，不能把整个字典当当前观测。
5. 采集器 `src/practice_control/collect.py:109` 中问题3使用 efficient + bounded refinement，问题4使用 triangular + bounded refinement；`refinement.py` 为缩小最终标签误差而增加最多每源2次、每局32次测量。因此库中轨迹费用是该采集策略的费用，不是冻结状态压缩基准的费用。
6. `src/simulation/q3_branch.py:97` 的 `make_q3_branch` 要求调用方提供一个假设 `Scenario`，只锚定历史实际坐标的反馈。其余动作由本地假设生成，不能把它误称为官方案例回放器。`simulation/cases.py` 的 Source 需要真实或假设的接收半径；`engine.py` 也需要误差模式。
7. 检索主工作树和现有 `q3-deep-rl-cpu-v2` 的 Python 源码，没有发现能从此库对新策略任意动作返回真实官方反馈的现成评估器。

## 冻结候选后的合法验证流程

### 1. 先冻结，再快照

- 先冻结候选和基准的代码提交、未提交文件哈希、配置、验证器源码、指标和判定标准。所有开发仅使用独立合成开发集；本库在这一阶段不打开内容。
- 使用现有 `practice_control.dataset_tools.snapshot(source, destination)`，入口位于 `src/practice_control/dataset_tools.py:40`，它从只读连接调用 SQLite `backup` API，输出到新的、不存在的目标文件。不要直接文件复制正在追加的SQLite，更不要改写原库或其journal。
- 快照完成后计算快照 SHA-256、字节数、schema、事务内表计数、生成时间、验证器及候选哈希并保存manifest。完整性检查在冻结副本上做。原库继续追加无需干预。
- 不要直接将已有 `stats` / `audit` 完整输出交给开发者：它们会输出标签精度和质量分布。新增“只含结构完整性与计数”的摘要入口更适合预检。数据库及含案例数据的副本应作为验证证据存放，不推送含坐标/隐私的公开Git附件。
- 预先按无内容依赖规则确定问题3验证范围、批次和一次性开封方案。若看到验证结果后修改候选，该批次必须标记已经用于反馈；不能反复使用同一批并宣称全新独立验证。新验证批次须事先冻结其选择规则。

### 2. 新增严格前缀回放客户端

建议新增离线 `PracticePrefixReplayClient`，对冻结副本读取每局步骤，仅向候选暴露与普通客户端一致的 state / enter / measure / clear / exit 接口。

- 对每个请求核验动作类型、频道及原始坐标；仅允许明确的序列化数值等价（如 -0.0 与 0.0），不得以邻近点/插值近似匹配。
- 严格按同一真实动作前缀推进，只有请求与记录动作相同，才返回该步已记录的官方响应并更新因果状态。
- 第一处不匹配立即标记 `unsupported_counterfactual_action`，停止该局回放，不返回下一步历史反馈、不提供未来状态、不伪造奖励；输出前缀长度和分歧动作类别即可。分歧本身不是算法失败，也不是成功，更不能用历史剩余费用给候选补齐总分。
- 记录日志缺失、重试、拒绝、正常退出等情况；同一request_id的重试不得重复计费或推进状态。不要悄悄跳过 rejected 动作、enter 或 exit。
- 只有完整前缀一致直到官方记录终点，才能声称“该候选在此轨迹上的动作/反馈/计费一致”。这种一致性不是新策略更快的证据。不得只挑未分歧案例计算平均收益。
- 测试应以人工构造的小数据库完成，包括首步/中途分歧、未读未来标签、同位置不同频道、顺序改变、clear后状态变化、重试、拒绝和数值边界。

### 3. 另做日志几何与计费审计

按真实日志逐步重建候选区域、已知频道及完整性证书，检查每个时刻的推断只使用当前及之前反馈；用题目规则重新计算移动、测量、换频道、检查和移除时间。冻结后的后验标签只允许事后检查范围包含关系或定位误差界，不能流回当时的策略输入。

该审计验证程序在官方反馈上的数值稳定性与约束正确性，不验证不同路线的完整清除率或总用时。若不同模块在同一真实前缀上给出不同候选动作，可以审查几何合法性，不能据此填造真实后续效果。

### 4. 整局策略比较仍使用独立可交互环境

- 主证据：独立合成场景的配对完整运行（基准与候选相同场景及噪声规则），和冻结后的官方演练。
- 本库：真实轨迹一致性与数学规则验证的补充证据，不充当任意策略的整局oracle。
- 若未来需要用源估计构造多组相容假设，可在冻结验证器下作为“有界重建场景的敏感性验证”，明确位置、接收半径、噪声均有不确定性；结果属于假设环境，不能报告为同局官方用时或独立官方成功率。也不得根据本库拟合这些假设的先验分布。
- 直接做离线重要性采样也没有现成保证：库里没有行为策略对任意连续动作的选择概率，确定性轨迹对未采取动作缺乏覆盖。不能把新的价值模型预测当可靠的官方反事实评估。
