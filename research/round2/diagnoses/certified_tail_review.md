# 确定性持证尾段的独立实现审核

本文件审阅 `q3-r2-certified-tail`，基准为 `8c624d08c61c0e411f93345d63a932b01ead4868` 的 `RelocatingStateSearch`。只读源码、配置和研究说明；不读取 SQLite，不修改候选树。实现完成后，经根任务授权独立运行其已有测试，未新开评估案例。结论：下列文件版本未发现阻断冻结的问题，满足本文限定的本地完整持证尾段比较条件；不是整局实验收益验收，也不是原问题的最优性证明。

## 可证明的命题及其边界

若在完全相同的实际调度边界，发现已经完成、所有未清源均已取得有效清除证书，此后无需新测量；又能精确重现基准从该状态直至结束的全部实际清除动作，则基准尾段是一条已知可执行上界。候选采用相同源集合，只执行通过重新核验的清除点，完整尾段的实际计费严格更低，并且整个冻结队列成功执行，那么该次替换的整局虚拟用时不高于基准。该论证不需要源真值、先知路径或预测下一次无线反馈。

保证是有条件的：仅针对同一前缀后的完整虚拟费用，既不证明原问题全局最优，也不保证 CPU 时间下降。若执行期间因状态不符、清除失败、协议拒绝、真实截止或动作预算而中断，‘回退到父策略’只恢复某种可执行行为，不能自动保住相对于原起点基准尾段的不退步证明。必须区分替换未接受、队列完整兑现、接受后证书前提失效。

## 基准中必须逐项重现的事实

|事项|`8c624d0` 的实际语义|错误近似的后果|
|---|---|---|
|任务排列|实际基准入口是 `RelocatingStateSearch._next_task`，每步重新按频道排序 sources；covers 在前。已知16源且开关开启才去除剩余 covers|使用一次 `result.order` 或保持旧数组下标，不等于滚动执行的基准|
|搜索预算|每次调用使用 `min(max_expansions, max_total_expansions-total_expansions)`，并加本步 `result.expanded`|逐步预算或排序不一致会改变后续 incumbent 与首选频道|
|源目标|`_target` 优先 near 点，否则返回 MEC 中心|中心是调度目标，不一定是真实动作点|
|certified clear|`EfficientSearch._clear` 将当前点投影到 `B(MEC中心, max(0,19.9-MEC半径))`|只比较中心路线会高估基准费用，产生虚假改善|
|near clear|`_resolve` 优先 near；父 `_clear` 对 `near_clear` 不作上述投影|near 与普通 MEC 圆不能混为同一种基准点位规则|
|频道费用|clear 不换 `current_channel`；每次成功 clear 固定光学3秒+清除2秒|错误增加清除切频费用会改变比较|
|是否实际执行|`EfficientSearch._execute_plan` 的 source 分支只传频道给 `_resolve`，忽略 task 中的 point|候选必须另有路径让排队点真正进入 `_perform`，否则规划优势不兑现|
|发现完成|剩余巡检全部完成，或合法观测已发现16源并启用公众上界规则|未来计划点、预计总源数、事后标签都不能当证据|
|动作和退出|`_check_budget` 使用 `self.actions`，为 exit 保留1次；enter 也计 actions|仅看剩余 source 数而不预留退出会导致尾段截断|
|虚拟预算|每步预检移动/5+5，且保留1微秒；客户端按响应维护计时|整段费用虽较短，也须与剩余额度和实际每步相容|
|16源终止|第16次成功 clear 后 `_perform` 抛 `_StopSearch`，随后 finally 退出|日志若只在正常返回处标记完成，可能误把成功队列记成未兑现|

父 `_resolve` 还会在开关开启时触发 `_share_observation`；冻结配置的该开关开启，但持证尾段仍无共享动作：near 直接跳过，普通区域半径至多19.9，而共享动作要求半径下降至少30，后验半径非负使该条件不可能成立。此论证也覆盖用户降低 `opportunistic_min_radius` 的情况。`replace_coverage=True` 已由父构造器拒绝。`blocked`、空区域、未完成扫描均进入资格或状态一致性判断。

## 冻结前的可验证条件

1. 接受判断的基准是逐步、同预算、同排序的实际 clear 尾段；需要人工构造含排序平局、耗尽预算、near/MEC 混合、16源提前停止的对照。
2. 每个排队清除点均通过当时合法几何证书；点位优化可不求全局最优，只要接受时完整可执行费用改善门槛成立。有限排列数不妨碍‘相对基准不退步’，但妨碍声称排列全局最优。
3. `simulation.engine` 对每段移动先四舍五入到整数微秒，再累加固定费用。若保证面向官方接口，还应声明依赖公布物理规则及计时容差，不能把本地实现的舍入方式当成已独立验证的官方内部实现。足够大的接受门槛可覆盖微秒级误差，但不能覆盖额外动作。
4. 候选不得因规划而改变实时位置、频道、已清/已知集合、区域、巡检列表或基准预算，除与父本次调用完全一致的变化；未接受时应沿原父选择继续。
5. 冻结队列执行必须核对预期前缀并直达实际点，不能被父类清除投影覆盖；清除失败必须撤销仍未执行部分，且将该次标为前提失效，而非继续记录‘保证节省’。
6. 退出和失败处理不应偷偷消耗下一条队列；成功第16源由 `_StopSearch` 结束也应得到正确的已兑现记录。低 real-time 余额应跳过额外规划；CPU 开销单独报告。

## 完成后的逐项检查

|检查项|实际实现与独立核验结论|
|---|---|
|基准继承与配置|候选继承 `RelocatingStateSearch`；两份 spec 的 config 和 enabled 相同，仅入口与名称不同。关闭新功能仍保留原覆盖重定位。原有 src 文件无修改。|
|资格与剩余集合|`_certified_disks` 只接受无 blocked、发现完成、2至4个全部持证未清源。16源判定只用 observed detected/cleared 与公众上界；未完成巡检且未达上界时不启用。|
|动态基准重现|`predict_baseline_tail` 每步取原 `solve_state_route` 首源，删除该源后保留频道排序，用实际旧安全点更新当前位置，用返回 expanded 更新影子总预算。无有效 covers 时父重定位没有候选，所以这正是父策略的尾段。当前父调用仍真实执行；预测首源及第一次累计展开数另作运行时比对。影子预算不写回实时状态。|
|点位差异|普通 MEC 源使用原半径 `19.9-r` 小圆；near 的基准仍回原 near 点，候选允许在该点周围14.9米圆内选择。后者是由 near 距源至多5米推导的新合法可行域，不能写成原 near 点位规则未变。|
|完整费用门槛|保留基准实际路线为 incumbent；候选至多24排列、每排列有界投影迭代。完整逐段计费至少改善10000微秒后才接受；不依赖优化器收敛或求得全局最优。|
|预算|先检查剩余 actions 能覆盖全部 clear 并留 exit；实时时间余额不大于10秒则保留父选择。完整基准费用须留至少1毫秒虚拟余量，超过4段移动取整与父未取整预检间的差。更低且同数量正费用的候选也在虚拟预算内。不能由10秒阈值推出CPU绝不会超时。|
|清除证书|接受前逐点核验 near 距离加5不超过 `20-1e-6`，或所有外包多边形顶点距离不超过该值；每步再次核验。没有预测反馈进入区域或已清集合。|
|实际执行与后状态|`_clear` 用继承 `_perform` 直接提交缓存点，避开原 `EfficientSearch._clear` 的重投影。预先构造后状态：位置、整微秒费用、频道不变、本频道加入已清、动作历史加1，并移除该源签名；随后对比实际状态，而不是无条件接受实际反馈为新预期。|
|正常终止|第16源在父 `_perform` 内成功后触发 `_StopSearch`，finally 仍记录已执行点并完成整条尾段日志；现有16源 fixture 实测通过。|
|失配、故障与截断|前状态变动或 clear 点失去证书时取消；成功后费用/状态不同也取消。清除失败标记前提失效。动作/时间中断由 `run` 收尾标记未完整执行，不把部分省时记成全尾优势。|

### 独立测试证据

独立执行 `python -m pytest tests/test_certified_tail.py -q`：初版32项通过，随后只增加低实时时间余额跳过规划的 guard 及测试，最终 **33项全部通过，3.09秒**。不是另开性能评估批，不读取真值验证库，也没有因观察案例表现而改变参数。

其中18组把预测结果与原父策略的**每个实际清除频道、每个实际坐标、累计微秒费用及最终展开数**核对，覆盖2/3/4源、near/MEC、总展开数0/59999/60000。另检查完整缓存实际执行、16源正常停止日志、预算不足沿基准、期中预算变更撤销主张、外部真实反馈引起签名失配、重合点与舍入两侧、禁用时逐动作等同基准。共享动作不出现由上文逻辑检查补充，不依赖偶然未触发。

现有 fixture 中 near 与 MEC 分组测试，没有穷尽一切混合区域、网络异常或浮点退化组合；源码的逐源分支与每步签名检查是进一步支撑，33项通过不是所有故障均已实测的声明。`git diff --check` 通过。

### 主张限定及剩余风险

1. 整局不退步需要首个修改之前的真实前缀与原v1相同，并且所有接受的尾段都完整执行、逐步核验通过。代码在取消后未来仍可能重新优化；后来一条记录 completed 只能证明相对**后来那个状态**的局部尾段支配，不能抹去此前接受后取消造成的前缀差异。任何接受后取消/中断都应撤销该整局的不退步主张。
2. 对未接受的计划，额外计算仍可能消耗真实时间；guard 降低风险但不证明硬实时保证。需在冻结后配对实验报告 CPU、虚拟用时、清除成功率、最坏局及原口径 T/LB。此源码审核没有新的整局性能数字，不能代替这些实验。
3. 逐步精确微秒签名针对本地确定性计费。官方响应若采用不同舍入/序列化，可能在已执行一次不同动作之后取消队列；不能预先宣称官方环境必不退步。需要演练验证兼容性，禁止正式测试。
4. 有效外包区域、静止源、无外部并发动作和客户端正确计费是物理证明的前提；签名检查发现某些前提破坏，不是针对恶意 Python 或异步外部修改的隔离安全证明。
