# Q4 第2轮：覆盖途中服务调度

基于 `1e58ce9`，固定 `compact_22` 几何和原中心/横向探测、光学网格兜底。
入口 `strategies.q4_r2_scheduling:run_q4_r2_scheduling`，仅预设两种配置：

| config | 16源发现停止 | 额外顺路服务 |
|---|---|---|
| cap16 | 16个真实正观测或已清除频道足以结束发现 | 无 |
| onroute | 同上 | 区域包围圆≤40m，经区域中心到下一覆盖站的绕行≤100m；单频道最多1次，全局最多4次，每次实际费用≤60s |

公共规则保证总源数≤16、每源独占一个频道。由合法反馈确认16个不同源后，
不可能还有未发现源；定位是否充分不影响这一计数证明。但是发现不等于清除：
策略仍逐源执行原定位/清除，并仅在16次实际成功清除后用计数证书终止。
不将未访问站点标为完成覆盖；只有15个已知源时仍保留原完整覆盖。

顺路服务不改变 `_next_probe` 或 `_resolve`。调度器在下一动作的保守费用
超过时间片时中断服务，保留真实观测，继续覆盖，最后仍调用原完整求解器。
清除按最坏5秒、测量按5秒及真实换频、移动向上取微秒估算门限。
四次时间片最多240秒是这些提前服务本身的预算，不是相对旧方法的总退化上界；
后续路径、观测和返回覆盖站的费用可能变化。时间片从出发前开始计费，
到区域中心及一次测量的预计费用必须容纳于该时间片。

先完成14项针对性测试，包括16发现不冒充清除、15源不得停止覆盖、超额动作
不发给客户端、时间片恢复、原探点/解算方法继承，以及人工10源场景与旧方法
完整动作轨迹逐值相同。人工案例只测接口与行为，不报告平均提速。

尚未运行新种子对比、数据库或官方演练。两种配置的性能由根任务统一新种子
配对评测，并同时报告旧口径 `conditional_guaranteed_all_clear_lower_s` 与 `T/LB`。
源计数停止可能过早失去有用视角，导致宽区域的光学兜底更慢，不能先验宣称改善。
