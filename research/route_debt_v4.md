# v4：把尚未完成的覆盖检查及候选绕路距离交给策略网络

本轮只检验一个表示假设：网络是否因为难以区分“仍有未知频道未检查的站点”和“只剩已知源频道未检查的站点”，低估了先处理附近已知源、再完成远处覆盖的价值。v4 增加 16 个输入，保留 v3 的候选集合、候选顺序、60 个旧特征、上下文、清除证书、奖励、回退和网络主体。它不加入规划器，也不替网络选择动作。目前只完成合法性、迁移和 CPU 验证，尚无 v4 训练收益结论。

## 1. 已有反馈提供的动机

输入是已经完成的公开开发验证：`cold-finetune-ppo-002/ppo_000384` 与同一 48 个场景的 rollout。只读动作、公开测量反馈、固定覆盖点配置和评估行，不运行验证场景，不读取真实源坐标。可复现脚本见 [audit_route_debt.py](audit_route_debt.py)，压缩输入逐个 SHA256、计数、代表局及成本均保存在 [observed_ledger_audit.json](route_debt_evidence/observed_ledger_audit.json)。

| 总计 | 3373.253 | 3162.245 | 211.008 |
| 移动 | 2553.378 | 2417.766 | 135.612 |

仍有明显的路线退化例子。场景 6011，动作下标 84 前，频道 2 的保守定位外包圆半径已经约 70.48 m；机器人离其圆心只需移动 132.50 s，却先去处理频道 6，随后向西完成覆盖。到下标 131 才从西南返回频道 2 的同一圆心，单程移动需 557.04 s。早期旧特征中的最近待检站点距源圆心 739.69 m，但真正仍有未知频道未检的最近站点相距 1888.39 m。这两个距离表示不同的后续任务结构。这里已有合法探点可选，不需要增加 axis 候选才能处理。

132.50 与 557.04 s 只是已观察状态的几何距离，**不能把差值称为可以实现的总时间节省**：提前处理会改变后续路线、观测和决策。该局用于提出可检验假设，不是反事实最优路径证明。

按 v4 实际采用的定义重放 48 局，6134 个物理动作前状态中，3443 个状态至少有一个“仅已知频道待检”的站点；22249 个已知未清源状态中，2116 个状态的两种最近站点距离不同，其中 1230 个相差超过 300 m。物理状态包含回退动作，并非全部为 actor 决策。未知集合始终取 `1..20 - detected`，没有夹带“发现 16 源就取消未知检查”的新规则。

重放使用归档 `summary.coverage_points` 的精确坐标。跨平台重新计算三角函数可能差约 `1e-13`，直接拿重算点作字典键会漏记实际测量；本次脚本修正了这个只读审计问题，实际控制器的精确记账规则没有改变。

## 2. 输入的精确定义

令当前机器人位置为 \(x\)，候选动作测量或清除位置为 \(q\)，七个现有覆盖点为 \(p_i\)。\(D\) 是实际检测到的频道集合；\(P_i\) 是现有账本中该站尚未测量、且对应源尚未清除的频道。定义

\[
U=\{1,\ldots,20\}\setminus D,\qquad n_i=|P_i\cap U|,\qquad I=\{i:n_i>0\}.
\]

新增 16 列如下，依照原有七站顺序排列：

1. 七列 \(n_i/20\)，表示各站还欠多少未知频道检查。
2. 七列几何绕行量：当 \(n_i>0\) 时，
   \[
   \delta_i(q)=\frac{\max(0,\|x-q\|+\|q-p_i\|-\|x-p_i\|)}{5000};
   \]
   其余为 0。速度为 5 m/s，因此这等于经过候选点再到站点的额外移动秒数除以 1000；这是几何输入，不是假设未来观测结果的代价估计。
3. 一列 \(\min_{i\in I}\|q-p_i\|/3600\)，无活跃站时为 0。
4. 一列 \(|I|/7\)，区分无活跃站与距离恰好为 0。

同一物理位置的不同频道候选复用这 16 列计算；频道本身、已知源几何和逐频道账本仍由旧 60 列区分。所有新增值在进入网络前检查有限性。`pending`、`detected`、站点坐标和当前位置全部来自公开配置或实际已发生反馈。

这些站点不是“今后必须访问”的预言：后来发现源、清除源或已有覆盖证书可能使检查变得多余。v4 只表达目前还欠的信息，绝不把未来计划当成已经完成。仅剩已知频道的站点也不被删掉，已知源在该点的观测仍可能有价值。

## 3. 如何隔离表示变化与初始策略变化

算法版本是 `q3-route-debt-ppo-v4`，特征模式明确为 76 维；动作模式仍为 `base`。v4 当前只接受 MLP、flat 分布、base 候选，拒绝同时混入 attention、group 校正或 axis 扩展。v1/v2/v3 的模式与检查点加载保持原样；paired 训练入口明确只允许 v1/v2/v3，不会静默接受 v4。

没有把原来的 60 输入线性层扩成 76 输入 GEMM。新编码为

\[
h_0=W_{60}f_{60}+b+Bz_{16},\qquad B=0,
\]

随后经过原有激活、线性层、mean/max 集合汇总、actor/critic。这样保留原 60 列线性运算的形状及连续内存布局，避免仅因改变矩阵乘法尺寸而引入初始舍入差异。`B` 直接以全零 Parameter 分配，不先随机初始化再清零，所以不会多消费 Torch 随机数。`B` 并没有冻结，真实 PPO 更新测试确认其获得非零权重。

显式 `--initialize-from` 可将 v3 权重迁入 v4；旧权重逐值复制，新增 `B` 为 0。v4 不能反向丢弃已训练的新权重；`--resume` 严格核对版本、模式和源文件清单。初始化状态中的 `preserves_initial_probabilities` 仅对相同特征版本，或本次核验的 v3→v4 路径，再加相同动作与概率模式时为真。该标记针对相同合法观测/候选历史，不保证后续学习相同，也不泛化到其他特征版本转换。

## 4. 已完成的验证与 CPU 成本

新增 10 项测试覆盖未知/已知账本分离、有限性、几何绕行、16 源发现边界、原控制器与新控制器完整轨迹、零迁移、首轮 RNG、PPO 实际更新、检查点恢复和 CLI。全部 `test_deep_rl*.py`、paired 与便携检查点相关测试共 187 项通过（41.71 s）。独立只读审查未发现 truth 输入、未来计划记账、回退变化或版本混淆。

[benchmark_route_debt.py](benchmark_route_debt.py) 用真实便携 best002 检查点，在训练场景 `110501..110532` 上各运行 v3/v4 两遍，前后交替执行，32 场景共 64 对：

- 完整物理动作、旧 60 列、上下文、候选数/顺序、教师标签及动作成本一致；全清且没有失败清除。
- 每局整批合法候选 logits 和 value 在本机 CPU float32 下 `torch.equal`，greedy 动作和虚拟总时长一致。
- 单线程平均 v3 为 0.32008 s/局，v4 为 0.36698 s/局，增加 46.89 ms，约 14.65%。特征阶段平均增加 23.36 ms。

数据、源码清单与检查点哈希见 [migration_cpu.json](route_debt_evidence/migration_cpu.json)。该时间含两边相同的记录及概率诊断开销，不含世界构造与事后整批等值检查；不是 GPU 训练吞吐预测。逐位等值是所测 CPU/dtype/kernel 的实证结果，部署端还需独立核对 GPU 初始化输出和固定验证完整轨迹。

## 5. 下一步实验与停止判断

根代理统一安排同 best002 起点、同新训练场景范围和同预算的 v3/v4 PPO 对照。新链从 `180001` 开始，避免与该初始化权重继承的训练链重叠；别的独立试验是否用过这些场景不等于本链泄漏。拟定两组各 512×32=16384 个采样场景，seed `9112037`，学习率 `1e-4`，entropy `0.005`，无 BC，4 个 CPU 采样进程，600 s 保存，2400 s 截止。旧/new 使用同一份本次源码，避免把版本开销变化混入比较。

```bash
PYTHONPATH=src:. Q3_SOURCE_COMMIT=<commit> python -m research_rl.train \
  --feature-version v4 --initialize-from <best002-u384.pt> \
  --architecture mlp --probe-candidates base --group-alpha 0 \
  --seed 9112037 --scenario-start 180001 --bc-episodes 0 \
  --updates 512 --episodes-per-update 32 --workers 4 --num-threads 1 \
  --lr 1e-4 --entropy-coef .005 --max-wall-s 2400 \
  --checkpoint-seconds 600 --output <fresh-v4-trial>
```

v3 对照只改特征版本和输出目录。先核验初始化逐局一致，再比较相同完成更新数的固定验证均值、尾部、失败率以及两组额外采样时间。若优势不稳定或相当于测量噪声，应保留负结果，不能仅凭输入更丰富就宣布 v4 更好。有限候选及部分观测仍使全局最优无保证；奖励与理论边界详见 [RL 算法依据](rl_algorithm_basis.md)。
