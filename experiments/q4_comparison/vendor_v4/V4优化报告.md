# 第四问 V4 再优化：让全局规划贯穿定位过程

## 1. 范围与主要结果

依据为用户提供的《B题.pdf》问题4、附录1—4，以及本对话的V3代码。以下方法是对现有算法的改动，实验是相同自建模拟器上的计算结果，不是官方成绩。

本轮冻结参数后，复跑之前1800例，增加600例未用于调参的新案例。V3和完整V4在2400个不同案例、31060个干扰源上均全部清除。累计平均每源时间从474.780721降到468.779636秒，下降1.2640%。

更重要的是独立新增600例：476.560154 → 470.197997秒/源，下降1.3350%。402例更快、185例更慢、13例持平；最差相对退步38.47%，最好减少31.11%。全2400例最差相对退步41.91%。因此只有平均收益证据，不能称为逐例优于V3。

## 2. 核心修改：局部定位不再一直执行到清除

V3的全局路线虽然同时包含扫描站和待清除源，但调用局部定位后会持续执行直至这个源被清除。新的示向度可能显著改变源的位置判断，局部程序却不能让全局调度器重新决定顺序。

V4每执行一轮成对RF检测，立即保存该源的位置外包多边形、最后一个有效示向度和锚点、正负观测、已执行轮数，然后返回全局循环。全局循环重新排列剩余站点和未完成目标。因此可以先处理其他目标或先去能顺便获得测向的扫描站，再回来继续原目标。

旧流程：

```text
选择A → 连续定位A → 清除A → 重新规划
```

新流程：

```text
选择A → 完成一轮成对测向 → 更新A的候选区域
      → 重新规划所有剩余站点和目标
      → 可能继续A，也可能先去扫描站或处理B
```

一次RF轮次仍保持原有的成对结构：先检测一侧，有信号则更新；无信号再测另一侧。两侧均无信号后才使用原来已证明的半平面排除。没有把普通单点无信号误解为附近不存在干扰源。

`complete=False`仅表示尚未完成、需要重规划，绝不等于成功清除。实际`clear()`成功反馈是删除待处理源的必要条件。

## 3. 有限步与不漏检保证为何仍成立

1. 全局发现仍使用同一21点布局及连续覆盖证书。对每个候选位置g，1000米内的检测点必须在凸包意义上包围g。题面给出有效半径下界1000米和180°定向覆盖，故该条件保证任意发射方向都能被发现。
2. 已发现源的定位区域始终采用保守外包，不用估计中心替代真实位置，不用概率粒子消失作为清除或频道不存在的依据。
3. 每个源单独持久化`rf_rounds`。返回全局循环不能把它重置为0。累计12轮快速成对检测后，进入原来的保守有限步定位程序。
4. 每次全局动作或者消耗一个扫描站，或者推进某个源的一轮RF检测，或者确认清除一个源。光学覆盖分支本身是有限的，最多按配置执行6或12次操作。因此重规划不会变成没有动作进展的无限循环。
5. 结束任务仍须满足原条件：确认清除16个源，或完成覆盖搜索并确认清除所有已发现源。已发现加已清除等于16时可以停止搜新源，但仍须清除待处理源。

程序加入全局动作数量检查；意外失败会显式报错，而不是给出虚假的成功计数。本轮测试全部在本地虚拟100小时上限之内；这里没有对任意网络故障或任意自定义配置宣称官方墙钟限时保证。

## 4. 光学覆盖上限：保留两个设置

沿用V3的覆盖法：对于定位区域的长L、宽W外包矩形，取安全半径r=19.5米，需要的检测点数满足

n = ceil(L / (2 sqrt(r² − (W/2)²)))，W < 2r。

将长边均分后每个小矩形的四角都在对应光学探测圆内。因此整组检测点有覆盖保证，完成只依赖实际成功反馈。

完整V4将允许的点数上限从6扩大到12；仅RF重规划版仍保持6。前者减少部分RF精定位，但会增加光学未命中操作。该设置来自两批开发集，不是查看新留出结果后反复修改得到的。

新增600例的消融：

|版本|秒/源|较V3平均改进|平均光学未命中次数/案例|
|---|---:|---:|---:|
|V3|476.5602|—|8.4450|
|仅扩大光学覆盖到12，不中断RF定位|476.4926|0.0142%|19.1667|
|每轮RF重规划，仍最多6个光学点|470.7488|1.2194%|6.9350|
|完整V4：RF重规划＋最多12个光学点|470.1980|1.3350%|15.4317|

只扩大光学覆盖的收益接近零，配对均值节约的95%正态近似区间跨越0。因此本轮主要有效因素是RF后的全局重规划，不是单纯增加光学尝试。

完整V4比6点版本平均只多节约0.5508秒/源。失败反馈和成本尚未核对时，改动较少的6点版本更值得先做真实演练；这不意味着6点版对每个案例都更快。

### 失败操作成本敏感性

本地计时为：移动距离/5＋5×检测次数＋频道切换次数＋3×光学操作次数＋2×成功清除次数。光学失败也计3秒。本地实现没有将失败丢弃。

按同一动作记录，将一次失败光学操作成本重新计为c秒，而成功操作成本保持不变：

T(c) = T(3) + (c−3) × 光学未命中次数。

相对于使用同一成本重新计时的V3，完整V4在c=3、5、10、15秒时分别约快1.335%、1.106%、0.540%、−0.020%；6点重规划版对应快1.219%、1.265%、1.379%、1.491%。

完整V4与6点重规划版的平均时间交点约为c=3.840秒。这里是固定策略动作记录的成本敏感性，不是已经核验官方失败接口。该交点也不是所有案例都成立的阈值。

## 5. 本地计算提速：缓存路线点对距离

旧多起点2-opt会反复计算相同的欧氏距离。新版一次构造距离矩阵，然后使用原先的候选顺序、比较阈值和破平局规则进行路线搜索，不引入近似距离。

500组独立随机路线问题中，新旧返回的完整访问顺序全部一致。交替运行、使用进程CPU时间测量：原程序1.226152秒，缓存版0.379917秒，该路线子程序约3.227倍快。

另有30个完整场景的逐动作轨迹等价测试：关闭RF中断并保持6点光学覆盖时，缓存版与默认V3轨迹完全一致。提供`solve_v3_cached()`入口。

必须区分：距离缓存加速的是计算，不会单独减少虚拟移动、检测或清除时间；不能把3.23倍子程序速度说成官方任务用时减少3.23倍。

- 开发一：81110000 + g×100000 + i，g=0…5，i=0…29；最初的小规模探索使用其中前10例。
- 开发二：82110000 + g×100000 + i，g=0…5，i=0…49。

## 7. 尝试过但未并入默认版的方向

- 光学检测顺序的期望到达时间动态规划、每个覆盖子区域的最近安全点、光学失败后重规划：开发集有小幅波动，没有大到值得增加默认复杂度的额外收益。
- 对旧路线施加惯性、使用下一探测点替代源中心参与全局路线、主动补测当前目标：个别设置有小幅收益，但不能稳定超过更简单的RF后重规划组合。
- 从全部历史正观测中重新选择锚点：收益很小。
- 更精细地裁剪1800米圆域：外包区域顶点增加会拖慢几何计算，开发集没有显著时间收益，默认没有采用。
- 多组少于21点的同心环布局：没有通过连续覆盖证书，未采用。这不是21点最少的证明。

## 8. 测试、局限与接入

20项单元测试全部通过，其中包含500组路线等价检查、30例逐动作等价检查、180个发射边界/极端误差的局部定位案例、跨全局循环的轮数保留、强制保底分支、私有环境数据不可访问包装，以及失败光学操作不误记成功。

完整V4在2400例中有1564例更快、783例更慢、53例持平。有限随机测试不能替代数学保证；平均优化不能替代逐例占优保证。

题面要求的三次正式测试和对应官方日志尚未执行。本包LOCAL_ONLY记录是自建环境动作记录，不能用于冒充官方日志。需要题目附件1、2的真实HTTP协议才能实现正式适配器，未猜造接口端点或返回字段。

## 9. 使用

```python
from q4_v4_solver import solve_v4, V4Config
from q4_v4_local import LocalConfig

# 完整V4，本地3秒失败成本假设下的平均时间较低。
report = solve_v4(device, V4Config())

# 沿用6点光学覆盖，集中使用本轮主要有效改动。
report = solve_v4(device, V4Config(local=LocalConfig(optical_cover_limit=6)))
```

每个入口都应在独立的初始会话上运行，不能在同一已清除过目标的会话内轮流试三种策略。
