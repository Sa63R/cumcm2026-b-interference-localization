# 第四问：带覆盖约束的多场景滚动前瞻规划

## 0. 本文的范围

本设计依据题面、已提供的 V4 源码，以及在线部分可观测规划与解析边缘化的文献。题面规定、既有程序行为、新提出的算法设计分开叙述。

本轮已完成：V4 决策代码检查；给定候选位置时的半径—方向解析边缘化原型；数量约束下的频道子集采样器；16 项单元测试；可复现的 V4 概率估计反例。

本轮没有完成：新方案的端到端在线求解器、与 V4 的新整例性能对比、官方模拟器接入。因此本文不报告新方案提速比例，也不把它命名为已经实测有效的 V5。

## 1. 选定的方法，而不是候选算法清单

采用“保守几何状态 + 用于决策的概率状态 + 短程闭环前瞻 + 可执行的保底策略”。每次同时决定下一检测位置、拟检测频道及检测后是否继续。主要优化目标为剩余完整任务时间，不是单次定位区域面积，也不是当前估计中心的旅行商路线长度。

V4 的可行区域、成对检测、清除成功反馈和 21 点覆盖保底保留。第一版只改变动作选择；确认有收益后，再允许沿路检测位置共同替代固定扫描站。

## 2. 对 V4 的具体检查

`q4_v4_solver.py` 将剩余站点和已发现目标的 `center()` 一起交给 `multi_route()`，选择第一项。已知目标仍被当作一个确定的中心点参加路线排序。

`q4_information.py` 的 `expected_radius_gain()` 使用三个候选位置，调用 `heuristic_visibility()`，按区域包围圆半径的预计减少量决定补测。默认收益阈值是 10 米，而不是预期节约的任务时间。

可复现反例：固定一个候选源位置 g=(0,0)，在 p=(500,0) 收到信号，在 q=(1200,0) 没有信号。因为两点从该候选源看来方向相同，p 有信号就意味着 q 也在发射角覆盖内，因此无信号只能说明 R<1200。在 r=(1300,0) 的接收概率应为 0，但原 `heuristic_visibility()` 返回 0.4。

这不是定位安全性错误：该函数只给动作排序。它说明现有排序没有完整使用信息。修正它并不自动证明最终路线更快。

## 3. 同时维护两种状态

### 3.1 用于正确性的几何状态

对频道 c 保存全部原始正负观测、示向度及其位置、强信号、光学反馈，以及包含所有合法候选位置的外包区域。完整隐状态包括是否存在、位置 g、半径 R、全向/定向类型和发射方向 u。

正信号必须满足距离、发射方向和（如返回示向度）±1°误差约束。负信号满足“距离超限或位于发射背面”，不能把这个逻辑或变成单一距离约束。观测为示向度还意味着距离大于 5 米；强信号对应距离不超过 5 米且可接收。

粒子权重为零、几次没有信号、后验存在概率很低，都不能删除合法的硬几何状态。新算法的概率计算也不能替代实际清除成功反馈。

### 3.2 用于动作选择的概率状态

对位置采用加权样本/自适应网格；给定位置后，尽量解析消去半径和方向，不在所有维度上盲目采样。所有概率依赖明确标注的规划先验，题面没有给出官方生成分布。

对未知频道保留“无源”与“有源”的概率；源总数严格限制在 10—16，各频道至多一个源，完整场景还应包含全向和定向两类。不能分别抛 20 次互相独立的硬币后不检查数量。

## 4. 半径与发射方向的解析边缘化

令 P+ 为正信号位置，P- 为负信号位置。固定候选位置 g，有：

L(g)=max(1000, max_{p∈P+} ||p-g||).

固定定向角 φ，u=(cosφ,sinφ)。若任一正观测不满足 u·(p-g)≥0，则该方向无效。对于在发射正面的负观测，必须有 R<||q-g||；背面负观测不约束接收半径。因此：

U(g,φ)=min(1500, min_{q∈P-, u·(q-g)≥0} ||q-g||).

连续均匀半径先验下，该位置—方向对应的半径证据为 [U-L]+/500。负观测产生的上界是严格的；连续积分不受单点端点影响，有半径端点原子质量时必须明确处理。

随着 φ 改变，正背面关系只在 atan2(p-g)±π/2 等有限角度处改变。因此将角度轴在这些点分段，在每段上半径上下界固定：

Z_dir(g)=Σ_j (区间长度_j/2π) × 合法半径先验质量_j。

全向情形没有角度积分，对所有负观测施加半径上界，得到 Z_omni(g)。两者按类型先验混合，并更新类型后验。不能每次收到新信息后仍强行保持全向/定向各 50%。

候选位置的后验权重，还应乘位置先验、示向度误差似然并除以位置采样提议密度。方位误差分布属于建模假设；同地点观测不能重复当成独立证据。原型只实现条件于候选位置的可见性部分，不声称已实现完整位置后验。

例：两种类型的初始先验各 1/2，半径内只有一次正观测时，正观测在全向下的概率是 1，在均匀随机朝向定向下的概率是 1/2，因此该候选位置的定向后验为 1/3，而不是 1/2。

这种“抽样一部分变量，解析消去另一部分”的结构借鉴 Rao–Blackwellisation；本题的角度区间与半径公式是根据本题观测模型推导。

### 4.1 未知频道与总数的联合采样

设已确认存在 k 个源，尚未确定的 m 个频道各有证据 λ_i=P(该频道历史无信号 | 有源)。假设原始计数先验是 π_N，给定 N 时从 20 个频道均匀选择 N 个。剩余存在频道集合 A 的后验权重为：

w(A) ∝ π_{k+|A|}/C(20,k+|A|) × ∏_{i∈A} λ_i，且 10≤k+|A|≤16。

用基本对称多项式的后缀动态规划计算每个 |A| 的权重，再按条件包含概率抽样集合；最多 20 个频道，不需要枚举 2^20 个集合。实现使用对数域避免很小似然连乘下溢。

该模块只处理数量与频道证据；完整场景组装还需要联合处理两类源均存在的约束和类型后验。

## 5. 动作不是“一个目标编号”，而是位置与操作组合

定义一个短宏动作为 a=(q,σ)，q 为下一停靠点，σ 为该点的短频道操作序列或有反馈条件的操作规则。只执行一个短动作，之后重规划，避免把一长串可能已经过时的任务锁死。

无线电部分的成本为：

c(a)=||q-p_current||/5 + 5K + Σ_{j=1}^K 1[c_j≠c_{j-1}]。

当前频道算入切换成本；不能默认每次检测都恰好花 6 秒。光学操作按接口真实语义单独计时。

候选动作包含：

1. V4 本来要执行的动作，始终保留作为比较基准。
2. 未访问覆盖站及其顺路点。
3. 已知目标的有效成对检测，或合法安全清除/有限光学覆盖动作。
4. 可以同时改善两个以上目标的共享测向点。
5. 完成剩余覆盖缺口的候选点。

共享测向点优先在目前路线的低绕行区域采样，例如对当前点 p 和前方路线点 r 要求：

||p-q||+||q-r||-||p-r||≤5τ。

τ 是允许的额外移动秒数。这能避免为了大交会角横穿整个区域。先产生有限候选并排序，再局部细化最好的坐标，不立即求整个连续空间的最优控制。

普通自由补测点不能套用成对负观测结论；只有真正完成满足几何条件的两个探测点，才能使用相应半平面排除。

## 6. 用未来完成时间给动作打分

从当前概率状态抽取完整、与观测一致的场景 ω_m；在相同场景上比较候选动作。场景只存在于规划器的虚拟模拟器里，真实环境只通过合法接口观测。

首版的一步 rollout：在场景 m 中执行候选 a，然后用基准策略 V4 根据模拟观测继续完成。记这一未来时间为 C_{m,a}，该场景的源总数为 N_m。目标为：

Q_hat(a)=1/M Σ_m C_{m,a}/N_m。

使用每场景的 T/N，而不是 E[T]/E[N]。如果优化的是每例完整总时间而不是每源时间，可以直接用 C，但必须与最终报告指标一致。

### 六条不可省略的实现条件

- 从当前完整状态继续模拟，不能把 V4 重新放回原点，也不能丢失已有测向和覆盖进度。
- 后续策略只能看到自己的模拟观测，不得读取场景内的真实源位置来安排下一步。
- 虚拟环境知道全部源已清除，不意味着策略有资格退出；模拟终止同样要求清除数量上界或覆盖证书。
- 同地点误差固定；已发生的观测保持不变，未来误差模型不应靠重复原地观测虚构信息。
- 后验更新保留多个可能状态，不能把刚刚生成一个示向度的那一个场景当作唯一真相。
- 全部候选用同一批环境样本和一致的误差场比较；观测不同导致后续路线不同，是合理结果。

一步闭环 rollout 先跑通，再增加 2—3 层有观测分支的前瞻。不要在每个场景中各自求一条预知未来的最佳路线，再取平均；那会错误地估计未来信息的价值。

### 6.1 风险与计算预算

记与基准动作的配对差为 Δ_m(a)=(C_{m,a}-C_{m,a0})/N_m。可用均值加上正向退步的尾部均值作为风险评分，例如 mean(Δ)+λ·CVaR_0.9(max(Δ,0))。λ 必须由开发集选择，不能看留出结果再挑。

候选先粗评，再用独立的新场景复核胜出的动作与基准，减少从一堆带噪估计中挑极端值的选择偏差。估计收益太小、误差条太大或计算超时，执行基准动作。有限抽样和模型不匹配下，仍然没有逐例或总体必定优于 V4 的保证。

起步可考虑 8—12 个动作、16 个粗评场景，再对两个优胜动作和基准追加 32—64 个场景。这只是待计时的初始配置，不是已验证能在限时内运行的参数。

V4 的完整后续运行可能很贵。先测单次续跑的耗时；只在重大路径分歧处做昂贵前瞻。若需要截断续跑，终端估值必须包含剩余定位和证明无遗漏的代价，不能只用已知源中心的最短路径。终端启发式引入额外误差，也使理论策略改进保证不直接适用。

把程序墙钟预算与虚拟行动时间分开；在线规划使用硬超时和基准动作返回。题面最长 20 分钟程序时间还包含通信，不能全部分配给搜索。尚不能对网络故障或未知接口耗时作保证。

## 7. 第二阶段：从固定覆盖站转为可验证的动态覆盖

第一阶段先固定 21 点，以隔离前瞻规划的效果。第二阶段才允许改变未来检测点。

令 S_c 为未知频道 c 已实际检测且无信号的位置集合。下列条件足以排除该频道存在源：

∀g∈D，g∈conv{p∈S_c:||p-g||≤1000}。

证明：若存在源 g，对任意发射方向 u，凸组合和为 0，所以这些距离范围内的检测点至少有一个满足 u·(p-g)≥0，理应收到信号，与历史全负矛盾。

四叉树证书对一个方格 B 先找到距离整个方格都不超过 1000 米的已测点，再检查其凸包包含四角。通过则整个方格排除；没通过则继续细分。数值不确定只保留未认证状态，不授权退出。

规划层可用未覆盖的位置—方向样本快速排序检测点；样本覆盖完不是终止证书。关键是按频道记账：走到过某点、不代表在该点检测了某频道。

此外要区分：

- “已完成的检测 + 承诺执行的未来检测”通过证书，只说明剩余计划有完成保证。
- 真正退出时，只能使用“已实际完成的检测”形成证书。

候选路线允许把顺路定位点、清除点纳入未来扫描，用连续覆盖检查授权替代。单步贪心覆盖面积可能忽略多个点共同形成凸包的互补性，因此不能套用普通独立覆盖的近似保证。可以短程联合选点，或用当前覆盖反例生成约束，逐步修正一条完整可行计划。

## 8. 正确性与性能分别证明

正确性来自硬几何约束、真实清除反馈、合法退出和可执行保底，不来自后验概率。

新动作允许自由补测时，应增加有限探索预算；耗尽后不可逆地回到已验证的有限步策略，避免在几个高信息点间无限摆动。只对真实完成的成对收缩增加该轮数，不能把任意自由测向都当成已证明的收缩。

理论上，精确已知同一概率模型、精确基准价值和适当终止条件下，rollout 有策略改进性质。实际的有限场景、截断估值和未知官方分布不满足这些理想条件，因此只能通过冻结参数后的配对留出测试验证平均改进，不能许诺每个案例不退步。

## 9. 代码改造顺序

第一步：拆开 V4 的大循环，把状态显式化。至少持久化位置/频道、remaining_sites、unknown_channels、pending、cleared、每频道全部观测、覆盖证书进度、RF 轮次和探索预算。旧策略抽成 propose_v4(state) 与 execute_and_update(state,action,device)，加入 resume_v4(snapshot,device)。先确认逐动作轨迹与原版一致。

第二步：接入本包的半径/方向边缘化与频道总数采样，在正观测外包区域内进行位置重要性采样。完整实现还需要示向度似然、静态误差条件采样和两类源存在约束；本包未伪装成已经实现这些部分。

第三步：保留原候选集做一步 rollout，检验打分本身是否有增益。再加入共享测向自由坐标，检验动作集合的价值。

第四步：加入动态覆盖重排和深度 2—3 的观测分支。连续观测树的粒子加权可参考 POMCPOW；只有推理质量证明有效后，再考虑 VOPP 式向量化或用学习模型蒸馏估值。

## 10. 验证矩阵

依次对比：A 原 V4；B 仅改概率推断；C 原候选集 + 多场景前瞻；D C + 共享测向候选；E D + 动态覆盖。不要一次加入全部组件后只报告总提升。

所有版本同案例比较，冻结参数后使用新留出集，报告清除率、均值 T/N、P95、最差相对退步、路程、无线电/切换次数、光学失败、最后清除之后用于证明无遗漏的时间、计算墙钟、保底次数。

除原有均匀/朝外边界/固定偏差，还应包含聚簇位置、不同半径分布、发射边界近切、空间相关测向误差等分布变化。它们是压力实验设定，不是官方分布的事实。

题目没有给定误差的概率密度、位置/方向生成分布及失败光学接口细节。真实演练首先验证接口和观测成本，然后校准用于排序的概率模型。三次正式测试不能作为反复调参集。

## 11. 本轮可运行原型

`radius_direction.py`：固定候选位置的半径/方向边缘化；下一点可见性；10—16 个源的计数约束和加权频道集合采样。支持连续均匀半径及端点离散质量。

`test_radius_direction.py`：16 项测试，包含正负观测一致性、半径上界、类型后验、方向旋转、同地重复、接收边界原子质量、数量动态规划与穷举对照。

`audit_v4.py`：输入原 V4 ZIP，复现 0.4 对 0 的反例，不改动原文件。

执行：

```bash
python -m unittest -v test_radius_direction
python demo.py
python audit_v4.py /path/to/B题第四问_V4优化版.zip
```

不要把该原型直接当作官方求解器运行；它没有移动/检测/清除的完整策略，也没有 HTTP 适配器。
