# 正式材料登记与审计

目前登记表的六个槽位尚无正式成绩，正式结果表保留空缺。程序代码、单元测试与本地研究结果不代替官方加密日志。

| 文件或目录 | 用途 |
|---|---|
| `正式测试登记.csv` | 问题 3、4 各三个槽位的正式证据索引，自动维护，不在 Excel 中手改字段 |
| `正式结果表.md` / `正式结果表.csv` | 从登记表生成的两张题目要求结果表，缺失结果保留待填 |
| `正式日志/问题3`、`正式日志/问题4` | `register` 按原文件名、原内容复制的官方加密日志 |
| `正式记录/问题N/slot-N` | 每局本地摘要与逐次请求记录的原样副本，仅在登记后创建 |

进入项目根目录，在官方界面核对成绩并导出原日志后，运行 `scripts/materials.ps1 -Action register`；详细参数见 [手动操作与正式测试指南](../资料汇总/手动操作与正式测试指南.md)。登记程序保存官方加密日志、摘要、明文请求日志的 SHA-256，防止后续无意改动。路径以登记表所在目录为基准，可将此目录整体复制到其他设备后复核。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\materials.ps1 -Action export-tables
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\materials.ps1 -Action audit
```

`audit` 返回 0 并输出 `ready_for_submission: true`，仅表示六次证据的内部一致性、文件完整性和已登记的人工上传确认通过。程序不能解密或验证官方日志来源，不能替代官方 GUI 的成绩核对及真实上传动作。日志导出文件需非空且每份不超过 2,000,000 字节。

`program_runtime_s` 来自人工抄录的官方 GUI；清除数和虚拟时间默认来自已接受的 HTTP 状态。若未确认动作仍在等待，必须从 GUI 成对提供清除数与总虚拟时间，登记为 `official_gui_user_transcribed`，不会自动用旧客户端状态填写。清除数为 0 时平均时间为 `undefined`。正式测试没有可验证真实源总数，因此本表不填写正式清除比例。

`confirm-upload` 仅记录你确认的上传状态，不负责上传。正式槽位重复登记会拒绝；归档目标同名且内容不同也会拒绝。中断登记后可用原输入重试，已有相同字节文件会保留。

最终支撑材料还需包含与论文对应的源程序、依赖/运行说明及实验配置，并把两张正式表补入论文重新生成 PDF。最终打包前请重新运行审计和文件大小检查；六份原始加密日志不可遗漏或改名。
