## 2. 最短运行方式：界面选好后输入队号

1. 打开官方模拟器，确认当前登录账户、联网和时间校验正常。
2. 先在官方界面启动对应题号的**演练测试**，等待准备、倒计时结束及接口就绪。
3. 在项目目录双击 `启动问题3演练.cmd` 或 `启动问题4演练.cmd`。提示时只输入当前登录参赛队号并回车，自动执行完整搜索及退出。
4. 保存终端打印的 `summary.json` 路径，在官方界面核对结果并导出记录。每次运行均新建结果目录，不覆盖前局。

也可以从 PowerShell 执行，启动脚本会自行切换到项目根目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_session.ps1 -Problem 3 -Mode practice
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_session.ps1 -Problem 4 -Mode practice
```

`-ExecutionPolicy Bypass` 仅对本次 PowerShell 进程生效。脚本不会替你选择题号或点击模拟器开始按钮；必须使脚本参数与界面一致。可传入 `-RobotId 参赛队号` 或设置环境变量 `CUMCM_ROBOT_ID`，不在源码硬编码队号。案例编码也可运行时用 `-CaseCode 编码` 记录，或结束后登记时补录。

默认策略为问题 3 的 `adaptive` 与问题 4 的 `triangular`，主动选点默认 `center`。可以用 `-Variant baseline|adaptive|deferred|triangular` 指定对照策略（`triangular` 仅适用于问题 4），用 `-ActivePolicy center|minimax` 指定主动选点；`minimax` 只在问题 3 生效，问题 4 保持几何中心启发式。`deferred` 与 `triangular` 都先完成覆盖扫描再定位清除，后者改用三角覆盖网格。每局摘要会记录实际采用的参数。

只检查端口，不发送模拟器动作：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_session.ps1 -CheckOnly
```

环境恢复或在其他 Windows 电脑首次运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

脚本依次寻找指定的 `-PythonPath`、`.venv-win`、本机 Codex Python 和系统 Python，要求 Python 3.10 以上。`setup.ps1 -WithTests` 会安装测试依赖并运行测试；`-WithReports` 会额外安装 Matplotlib。正常控制模拟器无需这两个选项，也无需激活虚拟环境。

## 3. 演练验收需要你记录什么

两问都先用不限次数的演练确认接口与完整策略可运行，保留多组结果。官方演练结果应记录案例编码、真实源总数、清除数、总虚拟耗时、程序运行时间、对应本地摘要及官方日志位置。

- 清除比例 = 清除个数 / 演练结束后官方界面给出的真实总数。
- 平均定位清除时间 = 总虚拟耗时 / 清除个数；清除 0 个时标为未定义。
- 本地模拟数据只用于研究和测试，不能作为官方演练或正式成绩。
- 返回 `completed: true` 表示程序在既定模型下完成覆盖、清除及正常退出，仍应与官方界面核对。
- 返回 `completed: false` 或退出码 1 表示预算耗尽、源未解决、模型/接口不一致或通信异常；摘要和已获得的动作记录仍会保存。

若需要单独验收四个接口，可在**新开的第三问演练**中执行附件 2 固定动作检查。它会主动退出该局，并非完整搜索：

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
.\.venv-win\Scripts\python.exe -m simulator_client smoke-practice --robot-id 参赛队号
```

## 4. 六次正式测试：逐局执行和登记

按题面及附件，问题 3、4 各有 3 次正式测试；正式测试启动成功即计次，中断也计次，不能继续原案例。请先完成演练验收，再在界面逐局启动正式测试。每局只启动一个控制程序，不同时双击多个入口。

每局操作顺序：

1. 在官方 GUI 核对题号、正式模式以及剩余次数，启动该局并等待接口就绪。
2. 双击对应的 `启动问题3正式.cmd` 或 `启动问题4正式.cmd`，输入当前登录参赛队号；也可运行 `run_session.ps1 -Problem 3 -Mode formal`。
3. 结束后核对案例编码、清除数、总虚拟耗时和官方界面显示的程序运行时间。导出该局原始加密行为日志，保留原文件名和原内容。
4. 在官方界面确认该日志上传成功。若尚未成功，先登记为待确认，稍后补记上传状态。
5. 用下面的命令登记，`Slot` 为该题的第 1、2 或 3 次。参数示例中的占位文字必须换成你本局真实值；不要照填示例数值。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\materials.ps1 `
  -Action register -Problem 3 -Slot 1 -CaseCode "本局真实案例编码" `
  -Summary "本局程序输出的完整路径\summary.json" `
  -OfficialLog "官方导出目录\保留原名的加密日志文件" `
  -Runtime 本局官方界面的程序运行秒数 -Uploaded
```

`-Uploaded` 仅在官方界面确实显示上传成功时使用；其含义是**记录你的核对结果**，不会上传文件。登记程序默认从最后已接受的 HTTP 状态读取清除数和虚拟时间。若需要采用官方界面核对数值，可以成对增加 `-ClearedCount 清除个数 -VirtualTime 总虚拟秒数`；程序会明确标注数据来自人工抄录的官方 GUI。

如果 `summary.json` 中存在 `pending_request`，最后一次动作执行结果尚未确认，必须使用上面的两个官方界面数值，不能把客户端旧状态作为正式结果。若界面也无法给出结果，保留文件，先通过官方模拟器支持渠道核实后再登记。

上传完成后补记确认（需与已登记槽位的案例编码精确一致）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\materials.ps1 `
  -Action confirm-upload -Problem 3 -Slot 1 -CaseCode "已核对上传成功的真实案例编码"
```

正式测试不显示真实源总数，因此不生成正式清除比例。平均定位时间采用虚拟时间，程序运行时间采用官方 GUI 的现实秒数，两者不能互换。若官方 GUI 的数值单位不是秒，应换算并保留截图便于复核。

## 5. 自动归档、结果表与材料审计

每次 `register` 自动完成：

- 验证正式模式声明、题号、案例编码及数值；防止六个槽位重复登记、同案例或同一份日志重复占槽。
- 将官方日志按原名、原字节放入 `支撑材料/正式日志/问题3` 或 `问题4`，校验非空且不超过 2,000,000 字节。
- 将本地 `summary.json` 和 `requests.jsonl` 原样归档到 `支撑材料/正式记录/问题N/slot-N`，为三份文件保存 SHA-256 摘要。
- 更新 `支撑材料/正式测试登记.csv`，使用相对登记表的路径，便于随支撑材料整体搬移。
- 生成 `支撑材料/正式结果表.md` 和 `正式结果表.csv`，分别列出两问的三次正式结果。缺失槽位显示“待正式测试”或留空，不用研究结果填充。

随时重新生成表格或审计：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\materials.ps1 -Action export-tables
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\materials.ps1 -Action audit
```

审计检查六槽唯一性、案例和日志重复、三个证据文件的存在及摘要、均值公式、HTTP/GUI 数值来源、上传确认。只有全部通过才输出 `ready_for_submission: true`。**审计是材料一致性检查，无法解密官方日志、鉴定其官方真实性或替你查看 GUI 上传状态。** 对官方 GUI 的人工核对仍是必需步骤。已有槽位或同名不同内容证据不会被自动覆盖。

结果表生成后，需把两问各三行正式结果补入最终论文，并重新生成最终 PDF；归档代码、依赖说明、实验配置和六份原始正式日志，最后核对提交包内容。

## 6. 中断、时限和最终仍需手动完成的事项

若程序报错或被中断，不要反复新开同局控制程序。先保存本局摘要与请求日志，并在 GUI 核对本局是否已经结束。未知动作结果会禁止后续新请求，避免重复清除或重复计费；测试已经关闭时无法通过新的 `/exit` 查询结果。程序的自动重试只在同一对象中保留原请求 ID 和内容。

按本地附件，每局现实窗口取“倒计时结束后 25 分钟”与“进入后最多 20 分钟”的较早截止；程序依据接口返回剩余时间运行。虚拟时间上限为 360000 秒。附件建议北京时间 **2026-09-13 15:30 前**完成六次正式测试；**17:30 后不能启动新测试**，为日志上传和论文核对留出余量。

最终由你完成的操作：

1. 官方 GUI 的登录、联网/时间校验、题号与模式选择、点击开始；如电脑缺少软件，再完成下载解压。
2. 首次输入实际参赛队号；核对两问充分演练结果，并保留官方反馈。
3. 逐局启动两问各 3 次正式测试，导出 6 份原名加密日志，逐份核对上传成功和 GUI 数值后登记。
4. 将已生成的正式表补入论文，核查学校/队号等真实信息、正文和支撑材料；电子稿从摘要开始、不放承诺书或编号页，按格式规范检查版式及页数。
5. 在竞赛提交入口完成最终 PDF 与支撑材料 ZIP 的上传及回执确认。格式文件要求电子论文和支撑材料各不超过 20 MB，正文不超过 30 页（附录不计入）；最终以提供的格式文件和提交界面为准。
