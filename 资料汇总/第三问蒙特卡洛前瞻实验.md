# 第三问蒙特卡洛前瞻：实现与成对验证

这是第三问的软件与实验记录。第四问策略不变，论文继续暂停。

## 本轮实现

新增 `variant="rollout"`，只允许问题3和 `active_policy="center"`。现有 `efficient` 保留为对照、模拟后续策略和计算失败时的后备策略。问题3默认入口暂仍采用已经完成官方演练的 `efficient`。

本轮只改宏任务调度：完成一个覆盖站扫频或一个源的定位清除后，重新决定下一项任务。候选包含当前 `efficient` 推荐、剩余覆盖点以及已发现源；候选数有上限。局部主动定位、整站频道扫描、19.9米保守清除条件、七点覆盖与16源上限认证沿用现有实现。

每次规划按以下顺序执行：

1. 只读取已接受的测量、清除历史和机器狗公开状态，抽样若干与历史相容的假设场景。
2. 对每个候选任务使用同一组假设场景，先执行该任务，再用 `efficient` 一直模拟至正常结束。
3. 累计完整剩余虚拟耗时，包括移动、换台、测量、光学检查、成功清除和剩余覆盖义务。未完成或退出失败的推演不能以较低费用胜出。
4. 候选收益达到阈值才改变选择，真实会话只执行选中的一个宏任务；收到后续反馈再规划。

这是根节点蒙特卡洛 rollout，尚未建立完整 POMCP 的动作—观测历史搜索树，也没有训练神经网络。[POMCP 原论文](https://proceedings.neurips.cc/paper/2010/hash/edfbe1afcf9246bb0d40eb4d8027d90f-Abstract.html)将粒子信念更新与蒙特卡洛树搜索结合；当前阶段先验证前瞻评价是否有用。

## 抽样假设与可行性

以下分布是研究假设，不是题目保证的官方生成规律：源数在10至16间均匀；给定源数，20个频道中等概率选取不重复子集；各源在半径1800米的圆盘内按面积均匀分布；接收半径在1000至1500米间均匀分布。

实际历史中的每个频道分别形成位置和半径约束：方向观测约束方位误差及接收距离，近场响应约束距离不超过5米，成功清除约束20米，失败清除排除20米圆盘；没有信号表示距离大于该源固定接收半径。成功清除之后的无信号不再反推原源位置。同点重复测量不会作为独立新证据重复加权。

对于一个候选位置，令历史允许的接收半径区间为 \([L(x),U(x))\)。从几何外包多边形均匀提议位置，用可行区间长度 \((U-L)/500\) 加权，再在该区间内抽取半径。源位置和半径在一次推演中保持固定。

已发现或已成功清除的频道必须存在；仅收到负观测的频道仍可能有源。设已确认存在的频道数为 \(k\)，其他频道存在时产生其历史的近似概率为 \(q_j\)，则源数抽样使用

\[
P(N=n\mid h)\ \propto\ \frac{e_{n-k}(q_1,\ldots,q_m)}{\binom{20}{n}},
\quad \max(10,k)\le n\le16,
\]

其中 \(e_r\) 为所有大小为 \(r\) 的子集的权重乘积之和。条件确定的频道证据与源数无关，约去；分母保留原先给定源数时均匀选择频道子集的概率。随后按相应子集权重抽取未知频道，避免把“没有测到”直接当成“不存在”。

采用有限提议池、近似的1.005度方位兼容带及新的未来误差种子，因此这是**近似条件分布**。未知频道在初批零命中时追加提议，自适应停止还可能高估罕见存在证据；1.005度带也比严格1度解释稍宽。不能把上述组合权重公式正确等同于整个程序精确贝叶斯抽样。有限池最终未命中可行位置时，如果不能用保守几何覆盖证明不存在，就返回采样失败，交给 `efficient`；不擅自删除该频道。

历史坐标的测量反馈在分支中固定复用，新坐标才生成未来误差。这保证过去同点反馈不会因为重新抽取种子改变，但不声称恢复了官方模拟器的随机误差机制。

## 候选比较和预算

若候选 \(a\) 在第 \(i\) 个假设场景中的完整剩余费用为 \(C_i(a)\)，基线任务为 \(a_0\)，则按成对差

\[
g_i(a)=C_i(a_0)-C_i(a)
\]

计算平均收益。只有

\[
\overline g(a)>\texttt{min\_gain\_s}
+\texttt{uncertainty\_penalty}\,\frac{s_g}{\sqrt M}
\]

才考虑替换基线任务，选择超过阈值最多的候选。相同假设场景用于所有候选，减少环境差异带来的比较噪声。单粒子时没有样本方差信息，标准误项记为零；这不表示确定无误。

这个标准误惩罚是启发式，不是置信保证。小粒子数、提议池近似、候选多重选择和模型偏差都可能导致实际变慢。经典 rollout 的改进性质需要相应评价与模型条件，不能把确定性优化中的结论直接套到本实现。[Bertsekas 的 rollout 综述](https://web.mit.edu/dimitrib/www/Rollouts_Survey.pdf)讨论了基于后续启发式进行前瞻评价的方法及其适用条件。

配置限制粒子数、候选数、规划次数、候选评价次数和累计规划墙钟时间。采样器和推演动作都检查合作式截止时间，并参考真实会话剩余时间预留5秒；达到限制就回到 `efficient`。该预留与后备策略不构成任意场景必能在现实期限内全清的证明。

假设分支延续当前公开位置、频道、虚拟费用和剩余动作预算，不重复原点扫描或重新计算已发生费用。分支没有按隐藏源数自动终止的机制：即使假设场景中10个源已全清，仍须支付未完成的空频道覆盖认证费用。在线代码不能读取真实源位置、接收半径或实际源数。

求解器冻结提交：`8da940f`。加入命令行、独立审计和分组归并后，全量回归452项通过，包括原问题4回归；随后补充1项推演内部计算超时的统计回归，相关归并器30项测试通过。新增检查覆盖抽样历史一致性、同点反馈、分支隔离、计时连续、来源不泄漏、相同公开历史和充足预算下同选择、未完成低费用分支拒绝及预算后备。

开发集：新的随机种子4000至4019，另加7个既有困难场景；三组预先登记参数与默认 `efficient` 成对比较，共108次运行。困难场景曾用于历史研究，不能称为独立留出样本。

选参规则为：先要求开发随机与困难场景全部清除成功，再在符合条件的配置中选择20个随机例的平均总虚拟时间最低者。困难例耗时倒退保留披露。开发完成后冻结这一组参数，再用新随机种子5000至5099作100例独立验证，不根据留出结果反复选参。若独立验证的成对节省区间仍跨零，不声称稳定改善。

独立验证分为4组，每组25个新场景，在本机并行运行。归并前核对各组场景连续且不重叠、参数与源码相同、没有缺例或筛掉失败记录，原压缩轨迹逐字节保留。并行墙钟耗时包含同机负载影响，单进程耗时参考开发实验；另核对规划是否因计算预算提前回退。

完整真值仅存入评估端归档，策略仅接收客户端公开状态和观测；每次运行的参数、代码摘要、完整轨迹、耗时分解和规划决策记录均保存。

主要比较全清成功率、完整总虚拟时间、每源时间 \(T/N\)、成对节省、尾部耗时、实际计算耗时与清除失败数。失败早停的低耗时不能视作优势。独立随机例的成对均值区间采用固定种子的2000次bootstrap；区间描述该研究分布的抽样不确定性，不覆盖官方分布偏差。

## 开发实验结果

108/108次运行全清，独立轨迹审计108/108通过；没有触发采样或规划预算后备。下表仅为20个随机开发场景，未将困难例混入随机均值。

| 策略 | 全清 | 平均总虚拟时间 | 相对当前efficient节省 | 平均程序耗时，串行 |
|---|---:|---:|---:|---:|
| 当前efficient | 20/20 | 3471.01秒 | — | 0.106秒 |
| 2粒子、3候选 | 20/20 | 3446.68秒 | 24.33秒，0.70% | 5.01秒 |
| **4粒子、5候选** | **20/20** | **3433.01秒** | **37.99秒，1.09%** | **15.13秒** |
| 4粒子、5候选，较高收益阈值 | 20/20 | 3458.54秒 | 12.47秒，0.36% | 14.78秒 |

按预先规定的规则选择4粒子、5候选。该配置11例较快、9例较慢，成对平均节省的95%区间为 **[-22.86，103.64]秒**，仍跨零。随机开发集p95耗时为3874.71秒，基线为3799.85秒；平均略好不等于尾部改善。最差退步为种子4004，增加202.79秒。

7个共享困难例全部全清，所选配置4胜、1负、2平；平均3577.47→3523.59秒，唯一退步是边界例增加1.34秒。所选配置在27例中实际改变46次宏任务选择、评价8908条候选续跑，实验并非始终退回旧策略。

同一随机开发集上的事后共同下界平均为1946.37秒，平均耗时/平均下界从1.7833变为1.7638。这只是对同一松弛下界的描述性比较，既不是全局近似比，也不是已经找到可达到的理论最短时间。

参数选择和输入摘要在 [`results/q3_rollout/selection.json`](../results/q3_rollout/selection.json) 中先行冻结。四组独立验证的求解器与参数均保持这一冻结状态；验证工具和开发归档随后提交为 `aa3fab0`。

## 100例独立验证结果

种子5000至5099，固定配置 `rollout_p4_c5` 与当前默认 `efficient` 各运行100次。两种策略均100/100全清，清除失败次数均为零。所有样本保留，没有重选参数、删差例或把开发案例混入本组。

| 指标 | 当前efficient | 蒙特卡洛前瞻 |
|---|---:|---:|
| 全清成功场景 | 100/100 | 100/100 |
| 平均总虚拟时间 | 3422.16秒 | 3368.32秒 |
| 各局每源时间T/N的均值 | 268.76秒 | 264.82秒 |
| 中位总虚拟时间 | 3399.05秒 | 3372.28秒 |
| p95总虚拟时间 | 4004.33秒 | 3867.14秒 |
| 最慢10%场景的平均时间 | 4071.43秒 | 3906.17秒 |
| 本组最大总虚拟时间 | 4552.92秒 | 4162.39秒 |
| 平均测量次数 | 131.21次 | 127.40次 |
| 平均移动距离 | 12944.95米 | 12778.38米 |
| 平均程序墙钟时间，本次并行负载下 | 0.103秒 | 14.366秒 |

平均节省 **53.84秒，即1.57%**；固定2000次成对bootstrap的95%区间为 **[16.30，89.12]秒**。本轮证据支持在所声明的本地研究分布上有小幅平均改善。它不证明每个案例都更快、不证明最优，也不能直接外推成官方生成分布或官方成绩的提升。

100例中54例变快、32例变慢、14例相同。最差退步是种子5072：3103.85→3597.07秒，增加493.22秒（约15.89%）；种子5094也增加417.47秒。虽然本组p95和最慢10%均值改善，逐案例风险仍然存在，不能只展示均值。

前瞻实际改变202次宏任务选择，完成32552条候选续跑。所有采样、未完成续跑及预算回退计数均为零，检查了推演内部触发截止的详细记录，确认不是因并行计算超时切回基线。平均规划时间14.26秒，单局最大规划时间21.79秒；串行开发的平均整局计算时间15.13秒，也表明额外计算是真实代价。

平均节省的53.84秒由移动减少33.31秒、测量减少19.05秒、换台减少1.48秒构成；成功清除的光学和移除费用相同。这个结果对应本轮实际改动的宏任务调度，不代表已经优化了覆盖点位置、局部主动测向或扫频频道顺序。

原始结果见 [独立验证统计](../results/q3_rollout/holdout/summary.json)、[逐案例数据](../results/q3_rollout/holdout/runs.csv) 和 [归并来源及摘要](../results/q3_rollout/holdout/manifest.json)。保留四个分片控制文件和全部原压缩轨迹；本地重复分片目录不加入Git，归并后的原始字节与摘要保留。

[独立轨迹审计](../results/q3_rollout/holdout/audit.json)200/200通过：28,851个动作的逐步计费差为零，两策略各清除1,295个真实源，合计2,590次成功清除；最大成功和认证清除距离均为19.3168米。覆盖/16源上限证书、退出、200行CSV及10,487次跨策略同点反馈一致性检查全部通过。

[事后共同下界](../results/q3_rollout/holdout/lower_bounds.json)平均为1908.10秒。平均耗时/平均下界从 **1.7935降至1.7653**，平均差额从1514.06降至1460.22秒。下界在全部策略完成后才使用真实源中心计算，未反馈给策略；它松弛了清除圆盘之间的路径和空频道排除费用，不保证可达。因此只能说本组结果离这个共同基准更近，不能说已经接近全局最优。

## 当前使用判断

第一阶段已经实现并完成本地独立验证：可以把新策略作为第三问的实验选项，改善幅度是1%量级，计算代价显著增加。默认入口继续保留已完成官方演练的 `efficient`；这版前瞻尚未做官方演练，因此本轮不替换已核验成绩。

继续实际接入时，需要在官方界面开启一局新的**问题3演练测试**，再使用下方冻结参数命令。完整POMCP搜索树、强化学习训练、局部动作扩展和第四问留作后续工作；本轮没有改写论文或运行正式测试。

## 代码与复现入口

- `src/strategies/rollout.py`：候选宏任务、完整剩余费用评价、限额与决策记录。
- `src/strategies/q3_belief.py`：只接收合法历史的假设场景采样。
- `src/simulation/q3_branch.py`：公开状态复制和固定历史反馈的本地续跑分支。
- `experiments/run_q3_rollout_comparison.py`：固定场景成对实验与失败保留。
- `experiments/q3_rollout_development_configs.json`：本轮三组开发参数。
- `experiments/q3_rollout_holdout_configs.json` / `q3_rollout_selected.json`：已冻结的批量实验配置与单局配置。
- `experiments/audit_q3_rollout.py`：独立计费、物理距离和覆盖证书审计。
- `experiments/merge_q3_rollout_shards.py`：先验证再归并全部分片，保留失败与原始字节。

在项目根目录运行：

```powershell
$env:PYTHONPATH = 'src'
.\.venv-win\Scripts\python.exe -m experiments.run_q3_rollout_comparison --output results/q3_rollout/development --configs experiments/q3_rollout_development_configs.json --random-count 20 --random-seed-start 4000 --include-hard --stage development
```

复现使用新的输出目录。`--allow-existing` 只允许续跑源码摘要、场景和配置完全一致的实验，保留已完成的失败或中断记录，不覆盖差例。
