# V6 Lite：演练与正式共用入口

算法版本仍为 `ed79530`，与此前 11 轮官方演练相同。只修改启动参数、模式日志及增加不连接模拟器的预检查。算法、模型权重、通信重试和单局运行流程保持原样。

## 在现有 Windows 虚拟机运行正式测试

打开命令提示符，先检查文件（此命令不连接模拟器）：

```bat
cd /d C:\Users\baiwc\Downloads\Q4V6Lite_20260913
C:\Users\baiwc\Downloads\Q4Practice\python\python.exe run_official.py --check-only
```

看到 `preflight_passed` 后，在官方模拟器中登录，选择第四问的正式测试。等待倒计时结束、接口就绪后执行：

```bat
C:\Users\baiwc\Downloads\Q4Practice\python\python.exe run_official.py --mode formal --robot-id 202627001104 --case-label Q4-FORMAL-1 --output formal_results\run1
```

`--robot-id` 必须和模拟器登录队号一致。`--case-label` 是自己的日志标签，也可填模拟器显示的案例编号。第二、三次分别改成 `Q4-FORMAL-2` / `run2` 和 `Q4-FORMAL-3` / `run3`；已有结果目录不会被覆盖。

程序每次只运行当前一局，不点击开始按钮，不开下一局，不改变模拟器模式。参数 `--mode formal` 只记录操作者已经在界面选择的正式模式；业务接口不能查询或切换这个模式。

## 演练用同一入口

把 `--mode formal` 改为 `--mode practice`，并使用新的输出目录即可。旧参数 `--practice-confirmed` 仍可用，等价于 `--mode practice`；`--formal-confirmed` 等价于 `--mode formal`。

## 结果与异常

程序会保存 `requests.jsonl` 和 `result.json`。正常结束应显示 `policy_completed_and_exited`；正式成绩和加密日志上传状态仍在官方模拟器中确认、导出。正式模式不通过源真值数量判断完成，仍使用原有覆盖证明或 16 个成功清除的上界证明。

现有通信客户端会以同一请求 ID 重试暂时失败的请求。进程或虚拟机崩溃后的断点恢复尚未验证。捕获到算法异常且没有结果未知的请求时，现有流程会尝试退出当前测试；不要把重新执行启动命令当作断点续跑。

这次仅检查入口两种模式的本地等价性，不表示已经完成正式测试。
