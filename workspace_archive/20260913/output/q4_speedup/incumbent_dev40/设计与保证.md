# 保留既有可行路线：固定构造与边界

实现位于 `code/experiments/q4_speedup/incumbent_route.py`，没有修改旧策略、冻结模块或原有 factory。提供 `incumbent`、`flex_incumbent`、`cells_flex_incumbent` 三种固定组合，不含可调路线阈值。

每次完整重规划时，以真实 `remaining` 中的站点和 `pending` 中的频道组成合法动作集合 L。先从上次路线删除已完成动作，保留其余动作的顺序；再对新增动作逐个选择欧式路线长度增量最小的插入位置。与原启发式产生的新路线使用同一当前位置、同一目标中心、同一欧式距离求和比较，返回较短者，相等时保留旧路线。

动作合法性：过滤后的旧路线由 L 中互不重复的元素组成；随后只插入 L 中尚未出现的元素，各插入一次。因此最终路线恰好包含 L 一次。代码对旧路线投影结果、新路线和每次执行前的动作集合均有断言。新目标不会遗漏，已清除频道和完成站点不会继续留在待执行路线中。

移站组合的 MRO 为 `FlexibleState → IncumbentMixin → [LocalState] → State`。先完成路线比较，再由原 `FlexibleState` 对首个站点提出移位并检查连续覆盖证书。保存的路线仍使用 `('site', id)` 标签；返回的 `('shift', id, point)` 只是该站点动作的执行形式，完成后依照同一个 id 删除，不会把移位当成新增搜索任务。

清除与停止条件没有变化：原真实反馈决定清除是否成功；达到16个已清除源或原搜索流程完成才能停止。少于16源结束时，测试另外验证实际扫描点的连续覆盖证书。决策函数未读取模拟器源位置等真值。

此构造只保证“同一决策时刻、同一估计中心下，选择的路线目标值不劣于两条候选”。它不保证真实任务时间不增加，也不保证未来发现全部源的时间提前。测向、目标不确定性、新增目标和提前停止都会改变未来问题。

已通过4项专属测试：200组随机投影/插入的完整动作集合与最小插入增量；保留较短路线及稳定平局且不修改安全状态；移位站点完成、目标清除和新目标插入；组合 MRO 顺序。随后每个端到端测试都继续逐轮检查合法动作集合。

已知最坏场景重放确实阻止了“站点8之后立即转外圈19”，但没有修复完整任务的尾部退步：新发现三个目标的最小增量插入选择了目标4，后续路线仍推迟发现频道3。不能把局部目标值改善表述为该场景已经修好。具体数值见 `known_worst_replay.json`；40场开发集不包含该已知最坏种子，也不作为新留出集。
