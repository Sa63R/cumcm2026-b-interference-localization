# 第四问调度与共享测量独立筛选

结论：不建议把调度候选并入新版主策略。66种改动方案中，没有可靠达到几个百分点的收益；V4原有“全局混合排序 + 适度共享测向”的平衡明显优于先扫完再追源、最近优先或不共享。

全部为本地自建场景，未操作 UTM 或正式/演练账号。开发筛选使用24个新场景，随后用另外60个新场景确认9个代表候选，共2340次完整求解，未出现漏源或异常。60场确认使用统一 bootstrap.py：包括真实全向/全定向、边界、聚簇、固定 ±1° 误差以及 0.01° 显示舍入，几何边界仍为 1.005°。每场保留原21站完整覆盖或16源上界证书。

这些数据是开发筛选，不能伪装成最终未见留出集。所有候选只使用 Device 的位置/频道/测量/清除接口；未向算法暴露模拟器真值。

仅把共享最低预期半径收益由10调到20，约节省0.084%（0.377秒/源）；探索性正态95%区间为[0.018,0.736]秒/源。它是多参数筛选后的微小收益，不值得为此声称明显提速，需和主要改进组合后重新做配对验证。

试验方向与失败原因：

- 按下一次真实动作入口点，而非源区域中心排序：24场慢0.6%～1.1%。将目标表示为独立进入点/离开点，有向路线在60场慢0.074%，局部随机位置误差抵消了静态路径优化。
- 一直续追、最近优先、站点优先、目标优先：均退步。先扫描再统一处理源在24场慢33.75%，最近优先慢7.24%。
- 将共享测向有效距离扩大至1000/1500m并下调收益阈值：增加大量无用检测，24场慢0.2%～3.4%。
- 仅在足够确定或探测点位于下一站途中时追源：16组半径/绕路阈值均变慢。60场轻度延后仍慢2.35%。
- 只有下一站预计缩小至少60%且绕路超过100m才延后：60场仍慢0.565%。
- 完全取消共享测向：60场慢13.70%，说明现有共享机制是必要优化。

接口：`schedule_candidate.ScheduleMixin` 可和其他 State 子类组合；`CandidateState(strategy="baseline")` 默认保持原策略。各策略都是可审计的开发候选，没有改写原始V4、官方适配器或其他代理文件。

结果文件：四轮筛选分别位于 screen24 / sharing24 / defer24 / gainwait24；统一60场确认位于 confirm60。每轮都有逐场 runs.jsonl、汇总 summary.json、配置 manifest.json。

追加站点访问顺序实验：14种内/外环优先、未覆盖可见场景质量/路程贪心等轻量规则也未得到稳定收益。全程面积贪心通常破坏TSP路线；内环优先慢3.14%，外环优先慢7.98%。仅前3次扫描且限制路程的两组在24场筛选略有正均值，60場确认均消失。
