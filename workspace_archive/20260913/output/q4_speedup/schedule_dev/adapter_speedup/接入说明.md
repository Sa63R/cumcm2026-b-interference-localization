# 新版演练入口与离线适配验证

新增 `code/experiments/q4_official_practice/run_speedup.py`，支持 `v4_fast`、`prior_fixed`、`cells_flex`、`combined`。旧入口、runtime、strategy、bench和候选策略文件没有改动。

每个策略先构造并导入所需模块，再安装 ExactComputeCache。prior_fixed 通过 state.planner 传入原 run_policy；seed只设置规划采样，不修改官方场景。当前版本为 q4-speedup-practice-20260912-v2。所有方法记录method、version、源代码SHA-256、cache_enabled、coverage_cache_enabled、CPU、wall、policy CPU/wall以及普通和覆盖证书两组缓存统计。prior_fixed仍有5秒决策预算，加速可能改变墙钟超时分支，不能声称其与未加速版逐动作相同。

必须在模拟器界面重新确认“第四问 演练”，再传 --practice-confirmed。该标志只是操作员确认；接口本身不能查询演练/正式模式。入口不提供任何正式测试操作。

C:\Users\baiwc\Downloads\Q4Practice\python\python.exe -u C:\Users\baiwc\Downloads\Q4Practice\code\experiments\q4_official_practice\run_speedup.py --method v4_fast --robot-id 202627001104 --practice-confirmed --case-label v4-fast-01 --seed 90210000 --output C:\Users\baiwc\Downloads\Q4Practice\practice_results

将 --method 替换为 prior_fixed / cells_flex / combined，并相应修改 case-label；不能在同一场景中重复连接不同方法。部署时除新入口外，必须同步整个 `code/experiments/q4_speedup` 的Python文件以及已存在的比较、协议和依赖目录；仅推送run_speedup.py不够。

离线验证通过真实SimulatorClient校验通道下的SyntheticClient，完全未发送网络请求、未操作UTM。3种方法各跑3场（真实全向、真实全定向、边界全定向），combined额外1场；加上V4对照，共13个完整求解，150个源全部清除。纯v4_fast在3场中与原V4的原始动作、反馈、虚拟时间及去除验证耗时字段后的报告完全相同。三场prior_fixed真实触发规划且无超时。

额外通过：缺少practice确认绝不构造客户端；真实客户端保留未知结果请求且不发新动作/exit；确定中断后正常退出；main入口写出带CPU/wall/版本/缓存配置的result.json。结果保存在results.json，测试日志位于上一级test_speedup_adapter.log和test_speedup_entry.log。

版本v2在构造策略后同时进入 ExactComputeCache 和 CoverageComputeCache；覆盖证书100输入非计时字段完全等价，证书CPU减少51.76%。该收益与之前32.36%的V4计算收益针对不同测量，不能直接相加。v2完整5项适配测试通过，v1原证据已保留到相邻adapter_speedup_v1目录。
