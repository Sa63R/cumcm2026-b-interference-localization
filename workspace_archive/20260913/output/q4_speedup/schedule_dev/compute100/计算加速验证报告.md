# 第四问计算加速：100场逐动作等价验证

已实现可选 `ExactComputeCache` 模块。本次100个新本地场景中，V4与加速版的 **34,237 条动作、全部反馈、虚拟时间、完成报告逐项完全相同**，1299个源全部清除，并通过覆盖/数量上界验证。

这项优化缩短计算用时，不改变任务虚拟用时和路线。

| 指标 | 原V4 | 加速版 | 减少 |
|---|---:|---:|---:|
| 100场合计CPU秒 | 2.176859 | 1.472425 | 32.36% |
| 100场合计墙钟秒 | 2.426404 | 1.649358 | 32.02% |

CPU加速约1.478倍。机器并非独占；每场两种版本交替先后顺序，记录 `process_time` 和 `perf_counter`，只做一次100场配对性能比较。统计包含动作日志记录、上下文安装/恢复与缓存清理，不包含相同的模拟器初始化、预热覆盖证明和事后验证。不能把这个百分比直接用于官方HTTP整体耗时。

具体改动：

- 同一不可变多边形的包围圆缓存：27,152次命中，10,631次计算。
- 包围圆支持点遍历顺序保持一致；若候选半径已经不可能满足原函数的更新条件，提前停止其剩余距离检查。
- 路由保留相同候选起点、整数编号打破平局、2-opt遍历、反转次序及浮点加法次序，减少分支、函数调用与重复索引。
- 半平面裁剪内联向量运算，保留每一步算术次序。
- 额外提供共享收益、光学覆盖、整条路线的有界缓存；在这100场单次V4求解中三者均无命中，主要为了后续重复前瞻场景复用，尚未测其前瞻收益。

缓存上限分别为包围圆2048、共享收益512、光学覆盖512、路线128条。实测单场峰值为包围圆192、共享收益64、光学覆盖26、路线49条；每场退出上下文清空，异常退出同样恢复函数。返回可变列表使用副本，调用者反转或修改不会污染缓存。禁止同进程重叠或嵌套上下文；并发使用独立进程。

接入方法（先导入并构造策略，再安装上下文）：

```python
from online import State, finish
from compute_fast import ExactComputeCache

state = State()  # 或先构造已导入的其他策略
with ExactComputeCache() as cache:
    report = finish(state, device)
statistics = cache.stats()
```

需在上下文外预先导入将使用的自定义策略模块，避免在上下文中首次导入模块而保留临时函数别名。几何常数在上下文期间保持固定。

验证还包括：247组路线逐项一致、10,000次半平面裁剪完全相同、1,200组不同量级多边形包围圆完全相同、光学结果变异隔离、缓存上限、显式清理、异常恢复与嵌套拒绝。100场使用10类场景（真实全向/全定向、边界、聚簇、固定正负极端误差等），物理误差1°，显示舍入0.01°，几何界1.005°。

`cases.jsonl` 保存每场性能与动作SHA-256；`identical_action_traces.jsonl.gz` 保存经两版逐项对照后共用的原始完整动作；`compute_fast_tested.py` 是性能测量时的冻结代码。全部是本地合成测试，未操作正式测试或UTM。
