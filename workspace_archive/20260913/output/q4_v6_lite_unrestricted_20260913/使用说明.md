# V6 Lite：演练与正式共用入口

算法版本仍为 `ed79530`，与此前 11 轮官方演练相同。演练和正式使用完全相同的启动命令，不用填写模式参数。算法、模型权重、通信重试和单局运行流程保持原样。

## 在现有 Windows 虚拟机运行演练或正式测试

打开命令提示符，先检查文件（此命令不连接模拟器）：

```bat
cd /d C:\Users\baiwc\Downloads\Q4V6Lite_20260913
C:\Users\baiwc\Downloads\Q4Practice\python\python.exe run_official.py --check-only
```

看到 `preflight_passed` 后，在官方模拟器中登录，选择第四问的演练或正式测试。等待倒计时结束、接口就绪后执行同一条命令：

```bat
C:\Users\baiwc\Downloads\Q4Practice\python\python.exe run_official.py --robot-id 202627001104 --case-label Q4-1 --output results\run1
```

`--robot-id` 必须和模拟器登录队号一致。`--case-label` 是自己的日志标签，也可填模拟器显示的案例编号。后续每局使用新的标签和输出目录，例如 `Q4-2` 与 `results\run2`；已有结果目录不会被覆盖。

程序每次运行官方模拟器当前打开的一局，不点击开始按钮，不开下一局，不改变模拟器模式。业务接口不能查询或切换模式，因此日志在未提供模式标签时写为 `unspecified`，不会猜测或冒称正式成绩。

## 兼容已有命令

已有的 `--mode practice`、`--mode formal`、`--practice-confirmed`、`--formal-confirmed` 参数仍然可以使用，但只是可选日志标签，不改变算法或通信流程。正常启动直接省略即可。

## 结果与异常

程序会保存 `requests.jsonl` 和 `result.json`。正常结束应显示 `policy_completed_and_exited`；正式成绩和加密日志上传状态仍在官方模拟器中确认、导出。正式模式不通过源真值数量判断完成，仍使用原有覆盖证明或 16 个成功清除的上界证明。

现有通信客户端会以同一请求 ID 重试暂时失败的请求。进程或虚拟机崩溃后的断点恢复尚未验证。捕获到算法异常且没有结果未知的请求时，现有流程会尝试退出当前测试；不要把重新执行启动命令当作断点续跑。

本次检查不填模式与各可选标签时的本地动作等价性，不表示已经完成正式测试。此前 11 轮官方演练验证的是同一算法与通信流程；修改后的入口仍需通过官方实际测试确认端到端效果。
